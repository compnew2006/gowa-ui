Facebook comments reply/status handlers now resolve the route `{id}` parameter as either the internal `facebook_comments.id` UUID or the Facebook Graph `external_id`, while keeping `organization_id` scoping. This prevents `/facebook/comments` reply/status actions from returning `Facebook comment not found` when the UI or older clients pass the Graph comment ID instead of the internal UUID. Regression coverage lives in `internal/handlers/fb_comments_test.go`.
