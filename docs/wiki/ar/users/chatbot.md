<div dir="rtl">روبوت الدردشة</div>

أتمتة محادثات واتساب باستخدام قواعد الكلمات المفتاحية، وتدفقات المحادثة، والردود المدعومة بالذكاء الاصطناعي، ونقل المحادثات بسلاسة إلى الوكلاء.

## إعدادات روبوت الدردشة

**Endpoint:** `GET /api/chatbot/settings`

عرض تكوين روبوت الدردشة الخاص بمؤسستك:

```json

  "enabled": true,
  "greeting_message": "مرحباً! كيف يمكننا مساعدتك؟",
  "fallback_message": "لم أفهم ذلك. يرجى كتابة 'مساعدة' أو الانتظار حتى يتواصل معك أحد الوكلاء.",
  "session_timeout_minutes": 30,
  "business_hours": {
    "monday": { "open": "09:00", "close": "17:00", "enabled": true },
    "tuesday": { "open": "09:00", "close": "17:00", "enabled": true },
    "wednesday": { "open": "09:00", "close": "17:00", "enabled": true },
    "thursday": { "open": "09:00", "close": "17:00", "enabled": true },
    "friday": { "open": "09:00", "close": "17:00", "enabled": true },
    "saturday": { "open": "10:00", "close": "14:00", "enabled": false },
    "sunday": { "enabled": false }
  },
  "ai_enabled": false,
  "sla_response_minutes": 15,

    "total_sessions": 1250,

  }
}
```

> **ملاحظة أمنية:** يتم تشفير مفاتيح واجهة برمجة تطبيقات الذكاء الاصطناعي قبل التخزين.

## ساعات العمل

تتحكم ساعات العمل في أوقات نشاط روبوت الدردشة. خارج ساعات العمل:

- يمكن تعطيل الأتمتة، مع وضع الرسائل في قائمة الانتظار للوكلاء
- يمكن إرسال رسالة مخصصة لوقت خارج ساعات العمل
- تظل الرسائل الواردة مستلمة ومخزنة

قم بتكوين جداول زمنية لكل يوم مع أوقات الفتح/الإغلاق وأزرار التمكين/التعطيل.

## إدارة الجلسات

كل محادثة مع روبوت الدردشة تنشئ جلسة:

1. **إنشاء الجلسة:** يتم إنشاء جلسة جديدة عندما يرسل جهة الاتصال رسالتها الأولى أو عند انتهاء صلاحية الجلسة السابقة
2. **مهلة الجلسة:** يتم تكوينها عبر `session_timeout_minutes` (الافتراضي: 30 دقيقة). إذا لم يحدث أي نشاط خلال هذه الفترة، تنتهي صلاحية الجلسة
3. **تتبع النشاط:** كل رسالة تقوم بتحديث الطابع الزمني `last_activity_at` للجلسة
4. **سياق الجلسة:** تتتبع الجلسة خطوة التدفق الحالية، وسجل محادثة الذكاء الاصطناعي، وقواعد الكلمات المفتاحية المطابقة

## قواعد الكلمات المفتاحية

أتمتة الردود بناءً على الكلمات المفتاحية في الرسائل الواردة.

### سرد قواعد الكلمات المفتاحية

**Endpoint:** `GET /api/chatbot/keywords`

### إنشاء قاعدة كلمات مفتاحية

**Endpoint:** `POST /api/chatbot/keywords`

```json
{
  "name": "حالة الطلب",
  "keywords": ["order", "tracking", "status"],
  "match_type": "contains",
  "response_type": "text",
  "response_content": "يرجى تقديم رقم طلبك وسأتحقق من الحالة لك.",
  "priority": 1,
  "enabled": true
}
```

| الحقل | الخيارات | الوصف |
|-------|---------|-------------|
| **match_type** | `exact`, `contains`, `regex` | كيفية مطابقة الكلمات المفتاحية مع الرسائل الواردة |
| **response_type** | `text`, `buttons`, `flow` | نوع الرد المرسل |
| **priority** | عدد صحيح (الأقل = أولوية أعلى) | ترتيب تقييم القواعد |

### تحديث قاعدة كلمات مفتاحية

**Endpoint:** `PUT /api/chatbot/keywords/{id}`

### حذف قاعدة كلمات مفتاحية

**Endpoint:** `DELETE /api/chatbot/keywords/{id}`

### كيفية عمل مطابقة الكلمات المفتاحية

1. يتم تحميل القواعد الممكّنة، مرتبة حسب الأولوية (الرقم الأقل أولاً)
2. يتم التحقق من كل قاعدة مقابل الرسالة الواردة باستخدام نوع المطابقة:
   - **Exact:** يجب أن تطابق الرسالة إحدى الكلمات المفتاحية تماماً
   - **Contains:** يجب أن تحتوي الرسالة على أي من الكلمات المفتاحية
   - **Regex:** يتم اختبار الرسالة مقابل كل كلمة مفتاحية كتعبير نمطي
3. يتم إرسال رد أول قاعدة مطابقة
4. إذا لم تطابق أي قاعدة، يستمر المعالجة إلى الذكاء الاصطناعي أو الرسالة الاحتياطية

## تدفقات روبوت الدردشة

إنشاء تدفقات محادثة متعددة الخطوات للتفاعلات المعقدة.

### سرد التدفقات

**Endpoint:** `GET /api/chatbot/flows`

### إنشاء تدفق

**Endpoint:** `POST /api/chatbot/flows`

```json
{
  "name": "حجز موعد",
  "description": "توجيه العملاء خلال حجز موعد",
  "trigger_keywords": ["appointment", "book", "schedule"],
  "steps": [
    {
      "id": "step_1",
      "type": "message",
      "content": "ما الخدمة التي ترغب في حجزها؟",
      "next": "step_2"
    },
    {
      "id": "step_2",
      "type": "input",
      "prompt": "يرجى إخباري باسم الخدمة",
      "next": "step_3"
    },
    {
      "id": "step_3",
      "type": "message",
      "content": "تم طلب موعدك. سيتواصل معك أحد الوكلاء للتأكيد قريباً.",
      "next": null
    }
  ],
  "enabled": true
}
```

### تنفيذ التدفق

1. عندما تطابق رسالة كلمات التدفق المفتاحية، يتم تفعيل التدفق
2. يتم تتبع الخطوة الحالية في جلسة المستخدم
3. كل خطوة ترسل رسالة وتنتظر رد المستخدم
4. ينتقل التدفق إلى الخطوة التالية بناءً على الرد
5. يكتمل التدفق عند الوصول إلى الخطوة الأخيرة، أو يمكن نقله إلى وكيل

### تحديث تدفق

**Endpoint:** `PUT /api/chatbot/flows/{id}`

### حذف تدفق

**Endpoint:** `DELETE /api/chatbot/flows/{id}`

## تكامل الذكاء الاصطناعي

تمكين الردود المدعومة بالذكاء الاصطناعي باستخدام مزودين خارجيين مثل OpenAI.

### التكوين

| الإعداد | الوصف |
|---------|-------------|
| **ai_enabled** | تبديل ردود الذكاء الاصطناعي تشغيل/إيقاف |
| **ai_provider** | اسم مزود الذكاء الاصطناعي (مثلاً `openai`) |
| **ai_model** | معرف النموذج (مثلاً `gpt-4`) |
| **ai_max_tokens** | الحد الأقصى للرموز لكل رد |
| **ai_system_prompt** | تعليمات النظام للذكاء الاصطناعي |
| **ai_api_key** | مفتاح واجهة برمجة التطبيقات (مشفر عند الحفظ) |

### كيفية عمل ردود الذكاء الاصطناعي

1. إذا لم تطابق أي قاعدة كلمات مفتاحية أو تدفق، يتم استشارة الذكاء الاصطناعي (إذا كان ممكّناً)
2. يتم تضمين سجل المحادثة (آخر N رسائل) كسياق
3. يتم تحميل وتضمين سياقات الذكاء الاصطناعي ذات الصلة (المطابقة للكلمات المفتاحية أو الثابتة)
4. يتم بناء الموجه من: موجه النظام + سياق الذكاء الاصطناعي + سجل المحادثة + الرسالة الحالية
5. يقوم مزود الذكاء الاصطناعي بإنشاء رد
6. يتم إرسال الرد كرسالة واتساب وتسجيله للتحليلات

### سياقات الذكاء الاصطناعي

**Endpoints:** `GET/POST/PUT/DELETE /api/chatbot/ai-contexts`

توفر سياقات الذكاء الاصطناعي معلومات إضافية لنموذج الذكاء الاصطناعي:

| نوع السياق | الوصف |
|--------------|-------------|
| **Static** | يتم تضمينه دائماً في الموجه |
| **Dynamic** | يتم تفعيله بكلمات مفتاحية محددة |
| **URL-based** | يتم جلبه من عنوان URL وتضمينه |

يتم ترتيب السياقات حسب الأولوية ومطابقتها مع الرسائل الواردة.

## نقل الوكلاء

نقل المحادثات بسلاسة من روبوت الدردشة إلى الوكلاء البشريين.

### سرد عمليات النقل

**Endpoint:** `GET /api/chatbot/transfers`

### إنشاء نقل

**Endpoint:** `POST /api/chatbot/transfers`

```json
{
  "contact_id": "contact-uuid",
  "reason": "طلب العميل وكيلاً بشرياً",
  "priority": "normal"
}
```

**ما يحدث:**

1. يتم إنشاء سجل نقل بحالة `pending`
2. يتم إشعار الوكلاء المتاحين عبر WebSocket
3. يتم تحديث تعيين جهة الاتصال

### استلام نقل

**Endpoint:** `POST /api/chatbot/transfers/pick`

يطالب وكيل بأقدم نقل معلق:

1. يتم العثور على أقدم نقل معلق
2. يتم تعيينه للمستخدم الحالي
3. تتغير الحالة إلى `assigned`
4. يتم إشعار الوكيل وجهة الاتصال

### تعيين نقل

**Endpoint:** `PUT /api/chatbot/transfers/{id}/assign`

تعيين نقل يدوياً لمستخدم محدد.

### استئناف بعد النقل

**Endpoint:** `PUT /api/chatbot/transfers/{id}/resume`

استئناف جلسة روبوت الدردشة بعد حل نقل وكيل.

## معالجة اتفاقية مستوى الخدمة (SLA)

تعمل مراقبة اتفاقية مستوى الخدمة (SLA) تلقائياً في الخلفية كل دقيقة.

### إعدادات SLA

| الإعداد | الوصف |
|---------|-------------|
| **sla_response_minutes** | الحد الأقصى للوقت قبل اعتبار الرد الأول متأخراً |
| **sla_resolution_minutes** | الحد الأقصى لحل المحادثة |
| **sla_escalation_minutes** | الوقت قبل التصعيد إلى مدير |
| **sla_auto_close_hours** | الإغلاق التلقائي للمحادثات بعد هذا العدد من ساعات عدم النشاط |
| **sla_escalation_notify_ids** | معرفات المستخدمين المراد إشعارهم عند التصعيد |

### إجراءات خرق SLA

عند خرق SLA:

1. يمكن إرسال رسالة تحذير إلى جهة الاتصال (إذا تم تكوينها)
2. يتم إشعار مستخدمي التصعيد عبر WebSocket
3. إذا تم تجاوز وقت التصعيد، يتم تصعيد المحادثة إلى مدير
4. يتم إغلاق المحادثات التي تجاوزت `sla_auto_close_hours` تلقائياً

### الإغلاق التلقائي

المحادثات المفتوحة لفترة أطول من `sla_auto_close_hours` يتم إغلاقها تلقائياً مع رسالة نظام تسجل السبب.

## معالجة الرسائل الواردة

عند وصول رسالة، يعالجها روبوت الدردشة بهذا الترتيب:

1. العثور على حساب واتساب
2. الحصول على جهة الاتصال أو إنشاؤها
3. حفظ الرسالة في قاعدة البيانات
4. التحقق من تمكين روبوت الدردشة
5. التحقق من ساعات العمل
6. التحقق من وجود جلسة نشطة
7. مطابقة قواعد الكلمات المفتاحية (حسب الأولوية)
8. مطابقة مشغلات التدفق
9. إذا كان الذكاء الاصطناعي ممكّناً ولم تطابق أي قاعدة، يتم استدعاء مزود الذكاء الاصطناعي
10. تطبيق الرسالة الاحتياطية إذا لم تطابق أي قاعدة
11. إرسال الرد
12. تحديث الجلسة
13. بث الرسالة عبر WebSocket
14. إرسال webhooks خارجية
