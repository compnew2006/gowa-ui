# Changelog

## [Unreleased]

### Added

- Repository maintenance: Hardened `.gitignore` with comprehensive patterns for all executable files, build artifacts (wildcards), and archive types (`.tar.gz`, `.zip`, `.7z`).
- Project memory: Initialized `RALPH_MEMORY.md` to persist technical learnings and prevent future regressions.

### Fixed

- Fixed repository synchronization by reconciling remote branch divergence via rebase and pushing all local tags.

### Added

- Added canned response multimedia + rich text capabilities:
  - Canned responses now support photo/video attachments stored as typed attachment metadata (`attachments` JSONB) with secure file cleanup on update/delete.
  - Added backend endpoint `POST /api/canned-responses/{id}/send` to dispatch canned response text and all stored attachments to a target contact through the unified outbound pipeline.
  - Added multipart form support to canned response create/update endpoints for uploading media attachments.
  - Settings UI canned response editor now includes a WhatsApp formatting toolbar (`*bold*`, `_italic_`, `~strike~`, `\`\`\`mono\`\`\``), placeholder insert shortcuts, and attachment management (add/remove media, validation, size limits).
  - Chat composer now recognizes canned responses with attachments and sends bundled media + text in a single canned-response send action.
- Added automated assigned-chat reset scheduling:
  - New organization settings: `assigned_chat_reset_mode` (`midnight` or `custom_hour`) and `assigned_chat_reset_hour` (0-23).
  - New backend worker `ChatAssignmentResetWorker` that runs every minute and resets assigned active chats to pending once per organization local day.
  - Reset worker persists daily execution marker `assigned_chat_reset_last_date` in org settings and broadcasts websocket `contact_update` events for affected chats.
  - Settings UI now includes an "Assigned Chat Reset Schedule" selector with midnight/custom hour options.
- Added chat reopen workflow and queue settings views:
  - New endpoint `PUT /api/chats/{id}/reopen` to reopen closed chats as **pending + unassigned**.
  - New settings pages/routes: `/settings/pending-chats` and `/settings/assigned-chats`.
  - Added queue shortcuts in `/settings` chat preferences tab for Pending, Assigned, and Closed chats.
- Added manual reopen controls in UI:
  - "Reopen Chat" button in closed chat read-only banner inside `ChatView`.
  - "Reopen" action in `ClosedChatsView` rows.
- Added explicit chat lifecycle support (pending/open/closed) across backend and frontend:
  - New chat lifecycle model helpers (`ChatStatus`, normalization, effective status derivation).
  - Contacts schema/index updates for `status`, `closed_at`, `closed_by_user_id`.
  - New chat lifecycle helper module for status/assignment filtering and transition payloads.
  - New chat API aliases and actions: `GET /api/chats`, `PUT /api/chats/{id}/claim`, `PUT /api/chats/{id}/close`, `GET /api/chats/{id}/messages`.
  - New Settings page route and view for closed chats (`/settings/closed-chats`) with read-only conversation access.
- Added chat store bucketed state management for `pendingChats`, `assignedChats`, and `closedChats`, including lifecycle actions (`fetchChats`, `claimChat`, `closeChat`, `fetchClosedChats`).
- Added secure registration-invite token flow:
  - New authenticated endpoint `POST /api/auth/register/invite` to generate signed, expiring invite tokens scoped to the current organization.
  - Updated users settings invite-link generation to include signed `invite` token in `/register` URL.
- Media file grouping & batch download: consecutive incoming media messages (images, videos, documents) sent within 60 seconds are now visually grouped with a "files sent together" label. A "Download All" button below each group zips all files with original filenames and triggers a single download.
- New `useMediaGroups` composable for timestamp-proximity grouping logic.
- New `MediaGroupBar.vue` component for group visual indicators and batch download.
- New "Chat" tab in Settings with a configurable media grouping window (15s to 5min presets).
- Added comprehensive activity audit trail support:
  - New `activity_logs` model + DB indexes for audit storage and filtering.
  - New authenticated endpoints: `POST /api/activity-logs` (custom events) and `GET /api/activity-logs` (own history with filters/pagination).
  - Automatic auth event logging (`login`, `login_failed`, `logout`) and engagement logging for user-authored conversation responses.
  - Global authenticated API interaction logging via `fastglue` after-middleware, excluding `/api/activity-logs` self-noise.
  - Hourly retention worker that purges logs older than 90 days.
- Added Activity Logs frontend UI at `/activity-logs` with filterable, paginated history and custom-event creation.
- Added Playwright E2E coverage for Activity Logs route and own-history filtering (`frontend/e2e/tests/activity/activity-logs.spec.ts`).

### Fixed

- Fixed Whatsmeow real-time sync for phone-origin outgoing messages:
  - `events.Message` with `IsFromMe` now persists/broadcasts when `DeviceSentMeta` indicates the message came from another linked device (mobile).
  - Locally-originated runtime echoes without `DeviceSentMeta` remain ignored to prevent duplicate outgoing records for dashboard/API sends.
- Fixed closed-chat auto-reopen behavior for inbound customer messages:
  - Incoming messages now auto-reopen closed chats to pending queue and clear assignment.
  - WebSocket `new_message` payloads now include `contact_status` and normalized `assigned_user_id` so frontend state updates immediately.
- Fixed chat privacy bypass risk by enforcing server-side restrictions on unassigned/pending chat message reads (`403` for non-admin users).
- Fixed closed chat access regression by allowing `GET /api/contacts/{id}` to return closed chats for read-only viewing while keeping send/reaction paths blocked.
- Fixed chat sidebar pagination regressions after tab split by making load-more logic tab-aware and aligned with `/api/chats` status/assignment filters.
- Hardened secrets-at-rest handling to remove encryption no-op behavior:
  - `Encrypt` now fails when account secrets are written without `app.encryption_key`.
  - Encrypted secret decryption now fails closed when key is missing.
  - Added startup encryption config validation and explicit account API error messages for missing key.
- Hardened inbound webhook trust and processing model:
  - Enforced signature validation for webhook POST payloads with app-secret resolution via phone ID / business ID.
  - Rejected invalid webhook object types and oversized webhook event batches.
  - Removed unbounded per-message/status goroutine fan-out in webhook request handling.
- Hardened queue/worker reliability and idempotency:
  - Added periodic pending-claim cycle for Redis stream consumers.
  - Added dead-letter queue path for poison/stale jobs after max delivery attempts.
  - Added recipient-level in-flight locks and skip logic for already-processed recipients to reduce duplicates.
- Fixed external endpoint routing divergence between worker/API code paths:
  - Worker now uses configured `whatsapp.base_url`.
  - Flow sync/publish/save/deprecate handlers now use configured WhatsApp client routing.
- Hardened custom actions runtime safety:
  - Added JavaScript execution timeout guard with bounded max timeout.
  - Moved redirect token storage to Redis-backed one-time tokens (with in-memory fallback only when Redis is unavailable).
- Hardened CORS and WebSocket origin defaults for cookie-authenticated sessions:
  - Removed allow-all fallback when `server.allowed_origins` is empty.
  - Added centralized safe-origin evaluation (same-origin + localhost loopback fallback only).
  - Unified CORS and WS `CheckOrigin` policy enforcement and added origin normalization.
  - Added regression tests for middleware and websocket origin validation paths.
- Hardened JWT secret handling to prevent silent authentication failure modes:
  - Added centralized startup validation that rejects empty/insecure placeholder secrets and enforces 32+ chars in production.
  - Added auth middleware fail-safe that returns 500 when JWT secret is blank/misconfigured.
  - Removed silent token-generation error swallowing in register/refresh auth flows.
  - Centralized handler-side JWT secret access for token signing and WS token validation.
- Updated configuration/docs to align with fail-fast JWT validation:
  - Replaced blocked placeholder JWT values in config templates with explicit required-secret guidance.
  - Added startup remediation guidance (`openssl rand -hex 32`) in README and configuration docs.
  - Improved JWT validation error messages to include actionable fix instructions.
- Fixed WhatsApp instance connection sync race and indefinite QR loading:
  - Backend now emits `instance_connected` during direct `Connect` success for already-linked sessions and handles lifecycle `events.Connected` to keep DB/websocket state consistent.
  - Async connect/reconnect failures now broadcast `instance_reconnect_failed` websocket events with user-facing error messages.
  - Instances UI now reconciles instance state via API after connect/reconnect requests, subscribes to failure/timeout websocket events, and surfaces explicit QR modal errors instead of waiting indefinitely.
- Fixed public registration org-boundary bypass:
  - `POST /api/auth/register` now requires a valid signed `invitation_token` and rejects missing/invalid/mismatched organization invitations.
  - Registration no longer trusts arbitrary caller-provided `organization_id` without cryptographic invitation proof.
- Fixed Activity Logs custom event modal wiring by switching to shared `CrudFormDialog`.
- Fixed chat sub-sidebar disappearing on some conversation switches: `ChatView` chat pane now uses `min-w-0` so long message content cannot force horizontal overflow and shift `#main-content` left.
- Expanded General Settings timezone options in `/settings` to include explicit UTC offset choices and city-based entries such as Cairo and Riyadh.
- Fixed canned response variable replacement to support both `{contact_name}` / `{phone_number}` and `{{contact_name}}` / `{{phone_number}}` formats when inserting replies in chat.
- Fixed stale WhatsApp startup state after server restart: instances left in `connecting` with no linked session (`jid` empty) are now reconciled to `disconnected`, so instance cards show `Connect / Scan QR` instead of getting stuck on `Connecting...`.
- Fixed linked-instance reconnect failures during startup leaving stale `connecting` status: failed reconnect attempts now set instance status back to `disconnected`.
- Added a QR refresh action in the WhatsApp QR modal: users can now click "Regenerate QR" to request a fresh code without closing the dialog.
- Fixed `/api/instances/{id}/reconnect` to force a real disconnect + reconnect cycle so QR regeneration reliably emits a new QR code instead of no-oping when a client is already active.
- Prevented duplicate WhatsApp instance names within the same organization: `CreateInstance` and `UpdateInstance` now trim names, validate case-insensitive uniqueness, and return `409 Conflict` with a clear error when a duplicate is requested.
- Fixed WhatsApp QR modal reopen behavior in `InstancesView`: QR payloads are now cached per instance with timeout awareness, so reopening the popup shows the current code when valid and falls back to loading/regeneration when expired instead of getting stuck on "Waiting for code...".
- Fixed WhatsApp group mention rendering when mentions arrive as LID tokens (e.g. `@524...`): inbound message normalization now resolves `mentionedJID` entries to real phone numbers and rewrites message text to display readable phone mentions (e.g. `@966...`).
- Fixed edited WhatsApp messages intermittently appearing as `[Unsupported message type]`: inbound parser now explicitly unwraps `ProtocolMessage.MESSAGE_EDIT` payloads (including wrapped variants) and extracts the edited content instead of falling back to unsupported.
- Enforced admin-only chat deletion: `DELETE /api/contacts/{id}` now requires admin role (or super admin), preventing non-admin roles from deleting chats even if they have `contacts:delete`.
- Fixed received messages showing as empty bubbles in UI: whatsmeow WebSocket broadcast in `events.go` was sending raw `content` string but frontend expected `content: {body: "..."}` object. Structured the WS payload to match the HTTP response format.
- Fixed `RefreshToken` handler discarding switched `organization_id` from JWT claims, which caused "contact not found" errors after token refresh when user had switched orgs.
- Fixed build failure in `MigrationView.vue` caused by incorrect `useToast` import and non-standard `showToast` usage; synchronized with the project's standard `@/components/ui/toast` implementation.
- Added missing `sync.WaitGroup` tracking to asynchronous instance connection handler to ensure graceful server shutdown.
- Fixed unhandled errors in `pkg/whatsmeow/adapter.go` and `pkg/whatsmeow/events.go` to ensure clean resource cleanup and pass static analysis checks.
- De-hardcoded media upload retry logic in Whatsmeow adapter, adding `upload_retry_count` and `upload_retry_delay_sec` configuration options.
- Added 30-second timeouts to background WhatsApp API calls (reactions, read receipts) to prevent orphaned hangs.
