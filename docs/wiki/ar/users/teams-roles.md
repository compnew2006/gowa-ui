<div dir="rtl">الفرق والأدوار</div>

إدارة هيكل فريق مؤسستك، وتحديد الأدوار بصلاحيات دقيقة، والتحكم في الوصول إلى الميزات من خلال التحكم في الوصول القائم على الأدوار (RBAC).

## إدارة الفرق

### سرد الفرق

**Endpoint:** `GET /api/teams`

عرض جميع الفرق في مؤسستك. يتضمن كل إدخال فريق عدد الأعضاء.

### إنشاء فريق

**Endpoint:** `POST /api/teams`

```json
{
  "name": "Support Team",
  "description": "Handles customer support inquiries",
  "member_ids": ["user-uuid-1", "user-uuid-2"]
}
```

**ما يحدث:**

1. يتم إنشاء سجل فريق
2. يتم إنشاء سجلات أعضاء الفريق لكل مستخدم محدد
3. يمكن تعيين المحادثات للأعضاء كمجموعة

### تحديث فريق

**Endpoint:** `PUT /api/teams/{id}`

تعديل اسم الفريق أو الوصف أو العضوية.

### حذف فريق

**Endpoint:** `DELETE /api/teams/{id}`

إزالة فريق. يتم تنظيف سجلات الأعضاء تلقائياً.

### إدارة أعضاء الفريق

#### سرد الأعضاء

**Endpoint:** `GET /api/teams/{id}/members`

#### إضافة أعضاء

**Endpoint:** `POST /api/teams/{id}/members`

```json
{
  "user_ids": ["user-uuid-3", "user-uuid-4"]
}
```

#### إزالة أعضاء

**Endpoint:** `DELETE /api/teams/{id}/members`

```json
{
  "user_ids": ["user-uuid-1"]
}
```

## الأدوار والصلاحيات (RBAC)

يستخدم Whatomate التحكم في الوصول القائم على الأدوار لإدارة ما يمكن للمستخدمين القيام به. كل دور لديه مجموعة من الصلاحيات محددة كأزواج `resource:action`.

### الأدوار المدمجة

| الدور | الوصف |
|------|-------------|
| **Admin** | وصول كامل إلى جميع الميزات والإعدادات |
| **Manager** | إدارة أعضاء الفريق، عرض التحليلات، معالجة التصعيد |
| **Agent** | معالجة المحادثات المعيّنة، إرسال الرسائل، استخدام الردود الجاهزة |

### سرد الأدوار

**Endpoint:** `GET /api/roles`

يُرجع جميع الأدوار لمؤسستك، بما في ذلك أدوار النظام والأدوار المخصصة، مع صلاحياتها محمّلة مسبقاً.

### إنشاء دور مخصص

**Endpoint:** `POST /api/roles`

```json
{
  "name": "Support Lead",
  "is_default": false,
  "permissions": [
    { "resource": "contacts", "action": "read" },
    { "resource": "contacts", "action": "write" },
    { "resource": "messages", "action": "read" },
    { "resource": "messages", "action": "write" },
    { "resource": "campaigns", "action": "read" },
    { "resource": "analytics", "action": "read" }
  ]
}
```

| الحقل | الوصف |
|-------|-------------|
| **name** | اسم الدور (يجب أن يكون فريداً داخل المؤسسة) |
| **is_default** | إذا كان true، يتم تعيين هذا الدور للمستخدمين الجدد افتراضياً |
| **permissions** | مصفوفة من أزواج الصلاحيات resource:action |

### الموارد والإجراءات المتاحة

| المورد | الإجراءات |
|----------|---------|
| `users` | `read`, `write`, `delete` |
| `roles` | `read`, `write`, `delete` |
| `contacts` | `read`, `write`, `delete` |
| `messages` | `read`, `write` |
| `campaigns` | `read`, `write`, `delete` |
| `templates` | `read`, `write`, `delete` |
| `accounts` | `read`, `write`, `delete` |
| `api_keys` | `read`, `write`, `delete` |
| `canned_responses` | `read`, `write`, `delete` |
| `flows_chatbot` | `read`, `write` |
| `webhooks` | `read`, `write`, `delete` |
| `analytics` | `read` |

### تحديث دور

**Endpoint:** `PUT /api/roles/{id}`

تعديل اسم الدور أو صلاحياته:

```json
{
  "name": "Senior Support Lead",
  "permissions": [
    { "resource": "contacts", "action": "read" },
    { "resource": "contacts", "action": "write" },
    { "resource": "messages", "action": "read" },
    { "resource": "messages", "action": "write" },
    { "resource": "analytics", "action": "read" },
    { "resource": "campaigns", "action": "read" },
    { "resource": "campaigns", "action": "write" }
  ]
}
```

**ما يحدث:**

1. يتم تحديث اسم الدور (إذا تم توفيره)
2. يتم حذف جميع الصلاحيات الموجودة
3. يتم إنشاء صلاحيات جديدة من الطلب
4. يتم إبطال ذاكرة التخزين المؤقت لصلاحيات الدور

### حذف دور

**Endpoint:** `DELETE /api/roles/{id}`

إزالة دور مخصص. **القيود:**

- لا يمكن حذف أدوار النظام (admin, agent, manager)
- يتم إعادة تعيين المستخدمين المعيّنين للدور المحذوف إلى الدور الافتراضي

### سرد الصلاحيات

**Endpoint:** `GET /api/permissions`

يُرجع جميع أزواج `resource:action` المتاحة التي يمكن تعيينها للأدوار.

## نظام الصلاحيات

### كيفية التحقق من الصلاحيات

1. عندما يقدم المستخدم طلب API، يستخرج وسيط المصادقة دوره
2. يتم تحميل صلاحيات الدور من ذاكرة التخزين المؤقت (عبر `GetRolePermissionsCached()`)
3. يتحقق المعالج مما إذا كان دور المستخدم يتضمن صلاحية `resource:action` المطلوبة
4. إذا كانت الصلاحية مفقودة، يتم إرجاع استجابة 403 Forbidden

### تخزين صلاحيات الدور مؤقتاً

يتم تخزين صلاحيات الأدوار مؤقتاً للأداء:

- مدة صلاحية ذاكرة التخزين المؤقت: 10 دقائق
- يتم إبطال ذاكرة التخزين المؤقت عند إنشاء دور أو تحديثه أو حذفه
- يتم تحميل ذاكرة التخزين المؤقت من قاعدة البيانات عند أول وصول

### تحديد نطاق محادثات دور الوكيل

يتمتع المستخدمون الذين لديهم دور **Agent** بقيود رؤية إضافية تتجاوز الصلاحيات القياسية:

| القيد | التأثير |
|-------------|--------|
| **رؤية المحادثات** | يرون فقط المحادثات المعيّنة لهم، أو المحادثات العامة، أو المحادثات التي هم متعاونون فيها |
| **إرسال الرسائل** | يجب أن يكون لديهم وصول إلى جهة الاتصال؛ لا يمكنهم الإرسال إلى محادثات لا يرونها |
| **المحادثات غير المطالب بها** | لا يمكنهم عرض أو الإرسال إلى المحادثات غير المطالب بها ما لم يتم تكوينها صراحةً |

هذا يعني أن الوكيل الذي لديه صلاحية `contacts:read` يرى فقط جهات الاتصال المعيّنة له، وليس جميع جهات الاتصال في المؤسسة.

### قيود الإرسال

يمكن للمؤسسات فرض قيود إرسال إضافية لكل مستخدم:

| الإعداد | الوصف |
|---------|-------------|
| **enabled** | تبديل قيود الإرسال لهذا المستخدم |
| **include_all_contacts** | السماح بالإرسال إلى جميع جهات الاتصال أو الأرقام المصرّح بها فقط |
| **authorized_numbers** | قائمة بيضاء بأرقام الهواتف التي يمكن للمستخدم مراسلتها |
| **allowed_instance_ids** | مثيلات واتساب التي يمكن للمستخدم الإرسال منها |
| **prefix_agent_name** | إضافة بادئة اسم الوكيل تلقائياً للرسائل |
| **allow_unclaimed_chat_view** | السماح بعرض المحادثات غير المعيّنة |
| **allow_unclaimed_chat_send** | السماح بالإرسال إلى المحادثات غير المعيّنة |

**تحديث قيود إرسال المستخدم:**

**Endpoint:** `PUT /api/users/{id}/send-restrictions`

```json
{
  "send_restrictions": {
    "enabled": true,
    "include_all_contacts": false,
    "authorized_numbers": ["+1234567890", "+0987654321"],
    "allowed_instance_ids": ["instance-uuid-1"],
    "prefix_agent_name": true,
    "allow_unclaimed_chat_view": false,
    "allow_unclaimed_chat_send": false
  }
}
```

### وضع الصادر

يمكن للمؤسسات التحكم في المراسلة الصادرة على مستوى المؤسسة:

| الوضع | الوصف |
|------|-------------|
| **inbound_only** | يمكن للمستخدمين فقط الرد على الرسائل الواردة؛ يتم حظر الصادر الاستباقي |
| **mixed** | يُسمح بكل من الردود الواردة والرسائل الصادرة الاستباقية |

### وضع النشر الصارم

عند فرض قيود الإرسال، يمكن للمؤسسات اختيار:

| الوضع | السلوك |
|------|----------|
| **audit** | تسجيل المخالفات لكن السماح بإرسال الرسائل |
| **enforce** | حظر الرسائل التي تنتهك القيود |
