<div dir="rtl">العلامات والتنظيم</div>

إدارة العلامات لتنظيم جهات الاتصال، وتكوين إعدادات المؤسسة، وإدارة الأعضاء، ومعالجة طلبات العملاء المحتملين، وإضافة ملاحظات المحادثات، واستيراد/تصدير البيانات.

## إدارة العلامات

تساعدك العلامات على تصنيف وتصفية جهات الاتصال (مثل `vip`, `lead`, `support`, `billing`).

### سرد العلامات

**Endpoint:** `GET /api/tags`

يُرجع جميع العلامات لمؤسستك مع عدد الاستخدامات:

```json
[
  { "name": "vip", "color": "#FF5733", "contact_count": 42 },
  { "name": "lead", "color": "#33C4FF", "contact_count": 128 }
]
```

يتم فرز العلامات أبجدياً حسب الاسم.

### إنشاء علامة

**Endpoint:** `POST /api/tags`

```json
{
  "name": "priority",
  "color": "#FF0000"
}
```

**التحقق:**

- يجب أن تكون أسماء العلامات فريدة داخل المؤسسة
- اللون اختياري؛ يتم تعيين لون افتراضي إذا لم يتم توفيره

### تحديث علامة

**Endpoint:** `PUT /api/tags/{name}`

تغيير اسم أو لون علامة. يتم تحديث جميع جهات الاتصال التي تحمل اسم العلامة القديمة تلقائياً.

### حذف علامة

**Endpoint:** `DELETE /api/tags/{name}`

**ما يحدث:**

1. يتم إزالة العلامة من جميع جهات الاتصال التي تحملها
2. يتم حذف سجل العلامة
3. لا يمكن التراجع عن هذا الإجراء

### استخدام العلامات مع جهات الاتصال

يتم تطبيق العلامات عند إنشاء أو تحديث جهات الاتصال:

```json
{
  "name": "John Doe",
  "phone_number": "+1234567890",
  "tags": ["vip", "customer"]
}
```

عند تصفية جهات الاتصال، يمكنك المطابقة حسب:

| الوضع | الوصف |
|------|-------------|
| **any** | جهة الاتصال لديها واحدة على الأقل من العلامات المحددة |
| **all** | جهة الاتصال لديها جميع العلامات المحددة |
| **has** | جهة الاتصال لديها أي علامات على الإطلاق |

## إدارة المؤسسة

### سرد المؤسسات

**Endpoint:** `GET /api/organizations`

يُرجع جميع المؤسسات التي لديك عضوية فيها.

### إنشاء مؤسسة

**Endpoint:** `POST /api/organizations`

```json
{
  "name": "Acme Corp"
}
```

**ما يحدث:**

1. يتم إنشاء المؤسسة
2. يتم إنشاء الأدوار الافتراضية (admin, agent, manager) تلقائياً
3. يتم إضافة المنشئ كعضو admin
4. يتم تهيئة إعدادات روبوت الدردشة الافتراضية

### المؤسسة الحالية

**Endpoint:** `GET /api/organizations/current`

يُرجع المؤسسة التي تنشط فيها حالياً.

### حذف مؤسسة

**Endpoint:** `DELETE /api/organizations/{id}`

> **تحذير:** يتطلب صلاحيات مشرف فائق. يؤدي هذا إلى حذف المؤسسة بشكل ممتد ويتسبب في حذف جميع السجلات المرتبطة (المستخدمين، الحسابات، الحملات، إلخ).

## إعدادات المؤسسة

**Endpoints:** `GET/PUT /api/org/settings`

تكوين إعدادات المؤسسة:

| الإعداد | الوصف |
|---------|-------------|
| **Timezone** | المنطقة الزمنية الافتراضية للجدولة وإعداد التقارير |
| **Business hours** | ساعات العمل لأتمتة روبوت الدردشة |
| **Default language** | اللغة الافتراضية للقوالب والرسائل |
| **Strict sending restrictions** | تمكين/تعطيل فرض قيود الإرسال |
| **Outbound mode** | `inbound_only` أو `mixed` |
| **Campaign draft only** | تقييد الحملات بوضع المسودة |
| **Strict rollout mode** | `audit` (تسجيل) أو `enforce` (حظر) المخالفات |

### تحديث الإعدادات

```json
{
  "timezone": "America/New_York",
  "business_hours": {
    "monday": { "open": "09:00", "close": "17:00", "enabled": true },
    "tuesday": { "open": "09:00", "close": "17:00", "enabled": true }
  },
  "default_language": "en",
  "strict_sending_restrictions_enabled": true,
  "outbound_mode": "mixed"
}
```

## أعضاء المؤسسة

**Endpoints:** `GET/POST/PUT/DELETE /api/organizations/members`

إدارة من ينتمي إلى مؤسستك.

### سرد الأعضاء

عرض جميع الأعضاء مع أدوارهم وحالة العضوية.

### إضافة عضو

إضافة مستخدم إلى المؤسسة بدور محدد:

```json
{
  "user_id": "user-uuid",
  "role_id": "role-uuid"
}
```

### تحديث دور العضو

تغيير دور عضو داخل المؤسسة.

### إزالة عضو

إزالة مستخدم من المؤسسة. لا يتم حذف حساب المستخدم نفسه — يفقد الوصول إلى هذه المؤسسة فقط.

## طلبات العملاء المحتملين

جمع العملاء المحتملين من الأدوات العامة على موقعك الإلكتروني.

### إنشاء طلب عميل محتمل عام

**Endpoint:** `POST /api/public/lead-requests`

```json
{
  "name": "Jane Smith",
  "email": "jane@example.com",
  "phone": "+1234567890",
  "message": "I'd like to learn more about your products.",
  "widget_id": "widget-uuid"
}
```

**ما يحدث:**

1. يتم إنشاء طلب العميل المحتمل
2. يتم إشعار مشرفي المؤسسة عبر WebSocket
3. يتم إرسال webhook صادر (إذا تم تكوينه)

### سرد طلبات العملاء المحتملين

**Endpoint:** `GET /api/lead-requests`

عرض جميع طلبات العملاء المحتملين لمؤسستك.

### تحديث حالة طلب العميل المحتمل

**Endpoint:** `PUT /api/lead-requests/{id}/status`

```json
{
  "status": "contacted"
}
```

| الحالة | الوصف |
|--------|-------------|
| **new** | عميل محتمل جديد، لم يتم التواصل معه بعد |
| **contacted** | تم التواصل مع العميل المحتمل |
| **converted** | أصبح العميل المحتمل عميلاً |
| **rejected** | لم يكن العميل المحتمل مناسباً |

## الإشعارات

**Endpoint:** `GET /api/notifications`

عرض إشعاراتك، مصفاة حسب النوع وحالة القراءة.

### تجاهل إشعار

**Endpoint:** `PUT /api/notifications/{id}/dismiss`

وضع علامة على الإشعار كمُتجاهَل.

### أنواع الإشعارات

| النوع | يتم تشغيله بواسطة |
|------|--------------|
| **Contact assigned** | تم تعيين جهة اتصال لك |
| **Chat transfer** | انتظار نقل من روبوت الدردشة |
| **SLA breach** | محادثة خرقت SLA الخاص بها |
| **Lead request** | تم تقديم عميل محتمل جديد |
| **Instance status** | تغير اتصال المثيل |

## ملاحظات المحادثات

إضافة ملاحظات داخلية إلى جهات الاتصال تكون مرئية لفريقك ولكن لا يتم إرسالها إلى جهة الاتصال.

### سرد الملاحظات

**Endpoint:** `GET /api/contacts/{id}/notes`

### إنشاء ملاحظة

**Endpoint:** `POST /api/contacts/{id}/notes`

```json
{
  "content": "يفضل العميل التواصل عبر البريد الإلكتروني بدلاً من المكالمات الهاتفية."
}
```

يتم وضع علامة على الملاحظات تلقائياً بمعرف المستخدم والطابع الزمني للمؤلف.

### تحديث ملاحظة

**Endpoint:** `PUT /api/contacts/{id}/notes/{note_id}`

يمكن لمؤلف الملاحظة أو المشرف فقط تعديل ملاحظة.

### حذف ملاحظة

**Endpoint:** `DELETE /api/contacts/{id}/notes/{note_id}`

يمكن لمؤلف الملاحظة أو المشرف فقط حذف ملاحظة.

## الإجراءات المخصصة

تحديد إجراءات HTTP مخصصة يمكن تشغيلها من تدفقات روبوت الدردشة أو يدوياً.

### سرد الإجراءات المخصصة

**Endpoint:** `GET /api/custom-actions`

### إنشاء إجراء مخصص

**Endpoint:** `POST /api/custom-actions`

```json
{
  "name": "Create Support Ticket",
  "url": "https://api.example.com/tickets",
  "method": "POST",
  "headers": {
    "Authorization": "Bearer secret-token"
  },
  "body_template": "{\"contact\": \"{{contact.phone}}\", \"message\": \"{{message.content}}\"}",
  "events": ["chatbot_no_match"]
}
```

| الحقل | الوصف |
|-------|-------------|
| **name** | اسم الإجراء المقروء بشرياً |
| **url** | عنوان URL الهدف (محمي من SSRF) |
| **method** | طريقة HTTP (GET, POST, PUT, DELETE) |
| **headers** | رؤوس مخصصة (القيم الحساسة مشفرة) |
| **body_template** | نص الطلب مع دعم العناصر النائبة |
| **events** | الأحداث التي تشغّل هذا الإجراء |

### تنفيذ إجراء مخصص

**Endpoint:** `POST /api/custom-actions/{id}/execute`

تشغيل إجراء مخصص يدوياً. يتم حل متغيرات القالب وإرسال طلب HTTP.

### إعادة توجيه الإجراء المخصص

**Endpoint:** `GET /api/custom-actions/redirect/{token}`

التحقق من رمز لمرة واحدة وإعادة التوجيه إلى عنوان URL المكوّن. يتم إبطال الرمز بعد الاستخدام.

## استيراد/تصدير البيانات

### تصدير البيانات

**Endpoint:** `POST /api/export`

```json
{
  "table": "contacts",
  "filters": { "tags": ["vip"] },
  "format": "csv"
}
```

| الحقل | الخيارات |
|-------|---------|
| **table** | جدول البيانات المراد تصديره (contacts, messages, campaigns, إلخ) |
| **filters** | فلاتر الاستعلام لتضييق نطاق التصدير |
| **format** | `csv` أو `json` |

يتم وضع عمليات التصدير الكبيرة في قائمة الانتظار وتكون متاحة للتنزيل عند جاهزيتها.

### استيراد البيانات

**Endpoint:** `POST /api/import`

تحميل ملف CSV أو JSON لاستيراد السجلات بشكل مجمع:

1. يتم تحليل الملف والتحقق منه
2. يتم فحص السجلات بحثاً عن أخطاء
3. يتم إدراج أو تحديث السجلات الصالحة بشكل مجمع
4. يتم إرجاع ملخص بعدد الإنشاءات والتحديثات والأخطاء

### الحصول على تكوين الاستيراد/التصدير

**Endpoints:** `GET /api/export/{table}/config`, `GET /api/import/{table}/config`

يُرجع الحقول المتاحة، والحقول المطلوبة، ومعلومات التنسيق لجدول معين.
