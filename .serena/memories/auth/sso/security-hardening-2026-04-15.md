SSO flow hardening in internal/handlers now relies on three controls: (1) Redis state also stores a browser-bound token and PKCE verifier, with a matching HttpOnly `whm_sso_state` cookie required on callback; (2) CallbackSSO rejects existing users unless the org matches the SSO config org and the provider binding is acceptable, with custom providers requiring an already linked SSOProvider/SSOProviderID; (3) custom provider URLs are validated before save/use and OAuth token exchange now runs through App.HTTPClient via oauth2.HTTPClient context so SSRF-safe transport is applied to token and userinfo requests. Tests in sso_handlers_test.go cover cookie mismatch, cross-tenant rejection, linked-vs-unlinked custom users, configured HTTP client token exchange, and private URL rejection in production.
