## Overview

Templates are reusable message blueprints that let your team send consistent notifications, updates, and OTP messages. They are stored per organization and managed either through the **Settings → Templates** page in the UI or through the [Templates API](/api-reference/templates) — there is no external approval workflow.

## Managing Templates (UI)

<Aside type="note">
  The Templates management page ships with the **`templates`** permission
  (`read` / `write` / `delete`), which is seeded automatically and granted to
  the **manager** and **admin** system roles. Agents don't see the page or the
  sidebar link. See [Roles & Permissions](/features/roles-permissions).
</Aside>

Templates are managed at **Settings → Templates** (`/settings/templates`),
reachable from the sidebar (between *Tags* and *Teams*). The page is a standard
list view with search, server-side pagination, and sortable columns:

| Column | Shows |
|---|---|
| **Template** | Display name (falls back to the normalized `name`) |
| **Category** | `MARKETING` / `UTILITY` / `AUTHENTICATION` badge |
| **Language** | ISO code (e.g. `EN`, `AR`) |
| **WhatsApp Account** | The account the template belongs to |
| **Updated** | Last-modified timestamp |
| **Actions** | Edit / Delete (gated by `templates.write` / `templates.delete`) |

### Create / edit a template

The **Add Template** / **Edit Template** dialog collects:

- **Name** `*` — normalized to `lowercase_with_underscores`; unique per
  account + language.
- **Display Name** — human-friendly label shown in the list and pickers.
- **Category** `*` — `MARKETING`, `UTILITY`, or `AUTHENTICATION`.
- **Language** `*` — e.g. `en`, `ar`.
- **WhatsApp Account** `*` — which account the template belongs to.
- **Header Type** — `NONE`, `TEXT`, `IMAGE`, `DOCUMENT`, `VIDEO`. The
  **Header Content** text field appears only when `TEXT` is selected.
- **Body Content** `*` — the message body with `{{1}}` / `{{name}}` placeholders
  (see [Template Variables](#template-variables)).
- **Footer Content** — optional footer text.

Validation matches the API: `name`, `body_content`, `whatsapp_account`,
`language`, and `category` are required; a duplicate (same account + name +
language) is rejected with a 409.

<Aside type="tip">
  Editing a template does **not** retroactively change messages already sent
  from it, and campaigns that reference it by `template_id` will pick up the
  new content on their next send.
</Aside>


## Template Structure

A template is composed of the following parts:

- **Header** - Optional header with type `TEXT`, `IMAGE`, `VIDEO`, or `DOCUMENT`
- **Body** - Main message content with variable placeholders (`{{1}}` or `{{customer_name}}`)
- **Footer** - Optional footer text
- **Buttons** - Call-to-action or quick reply buttons
- **Sample values** - Example values for the placeholders

Authentication templates additionally support:

- **Security recommendation** - Adds "For your security, do not share this code." to the message
- **Code expiration** - An expiration countdown footer (1–90 minutes)

### Template naming

Template names are normalized automatically: lowercased, with spaces and hyphens converted to underscores (e.g. `Welcome Message` becomes `welcome_message`). The `name` + `language` combination must be unique per WhatsApp account.

## Template Variables

Templates support dynamic variables that are replaced with actual values when sending messages.

### Positional Parameters

The traditional format uses numbered placeholders `{{1}}`, `{{2}}`, etc.:

```
Hello {{1}}, your order #{{2}} has been shipped!
```

When sending, you provide values in order:
- `{{1}}` → Customer Name
- `{{2}}` → Order ID

### Named Parameters

Templates also support named parameters for better readability and maintainability:

```
Hello {{customer_name}}, your order #{{order_id}} has been shipped!
```

Named parameters make templates easier to understand and less error-prone when dealing with multiple variables. When creating templates with named parameters:

- Use descriptive names like `{{customer_name}}`, `{{order_id}}`, `{{delivery_date}}`
- Parameter names can contain letters, numbers, and underscores
- Whatomate automatically detects whether your template uses positional or named parameters

<Aside type="tip">
  Named parameters are recommended for templates with 3 or more variables, as they make the template easier to understand and maintain.
</Aside>

### Header Variables

A TEXT header can contain **at most one** variable — a Meta restriction
that Whatomate enforces at template creation time. Both positional (`{{1}}`)
and named (`{{season}}`) work; mixing positional and named within the same
template (header + body) is still not allowed.

When sending:
- **API**: pass the value via the `header_params` field on
  [Send Template Message](/api-reference/messages/#send-template-message). It
  falls back to `template_params` if omitted — convenient for named templates
  where the header variable name doesn't collide with a body variable.
- **Campaigns**: add a `header` column (always before the body parameter
  columns) in your CSV or manual entry. The dialog can generate a sample CSV
  with the right columns for you. See
  [Adding Recipients](/features/campaigns/#adding-recipients).

### Media headers (Image, Video, Document)

Templates with an `IMAGE`, `VIDEO`, or `DOCUMENT` header are sent with the
media supplied **at send time** — not stored on the template. When sending
from the chat composer, attach the media file; when sending via the API, use
the `header_media_url` field or upload a `header_file` via multipart form on
[Send Template Message](/api-reference/messages/#send-template-message).

### URL Button Variables

Templates can include URL buttons with dynamic variables. For example, a "Track Order" button with URL `https://example.com/track/{{1}}` will prompt you to enter the dynamic URL value when sending the template from the chat view.

When sending via the API, provide button values using the `button_params` field (keyed by the zero-based button index). See the [API reference](/api-reference/messages/#send-template-message) for details.

## Using Templates

Templates can be used in:
- **Direct Messages** - Pick a template from the chat composer and fill in its parameters
- **Campaigns** - Bulk send to multiple contacts, with parameters from a CSV or manual entry
- **API** - Programmatically via the [Send Template Message](/api-reference/messages/#send-template-message) endpoint
