بناء نظام الـ Authentication الكامل (JWT)
Login، Register، Refresh Token، Logout، Switch Org، WebSocket Token
أبني نظام Authentication لمنصة WhatsApp Business متعددة المستأجرين (Multi-tenant). متطلبات النظام: 1. Login بالإيميل وكلمة المرور (bcrypt) 2. JWT Access Token (مدة قصيرة 15-60 دقيقة) 3. JWT Refresh Token (مدة طويلة 7 أيام، يُخزن في Redis) 4. Refresh Token Rotation (كل refresh ينشئ pair جديد، القديم يُلغى) 5. Logout (إلغاء الـ refresh token من Redis) 6. Switch Organization (تغيير الـ org الحالية دون تسجيل خروج) 7. WebSocket Token خاص (30 ثانية، single-use، للـ WebSocket فقط) 8. Invite Token للتسجيل (موقّع، مرتبط بـ org) 9. HTTP-only Cookies للـ tokens تفاصيل مهمة: - كل JWT يحتوي على: user_id, organization_id, role_id - الـ refresh token يُخزن JTI فقط في Redis - عند switch org: tokens جديدة بـ org_id جديد - حماية من Timing Attack في التحقق من كلمة المرور المطلوب: اشرح لي تصميم هذا النظام خطوة بخطوة مع توضيح: 1. ما هي الـ endpoints المطلوبة؟ 2. كيف يعمل Token Rotation؟ 3. كيف أتعامل مع Multi-org للمستخدم الواحد؟ 4. ما هي حالات الحافة (Edge Cases) التي يجب التعامل معها؟

بناء Middleware الأساسية
Auth Middleware، Multi-tenancy Scope، CSRF، Security Headers، Rate Limiting، Request Logger
أبني Backend API لمنصة WhatsApp Business. أحتاج تصميم middleware chain متكاملة. الـ Middleware المطلوبة بالترتيب: 1. CORS Handler 2. Security Headers (X-Frame-Options, X-Content-Type-Options, إلخ) 3. Request Logger 4. Panic Recovery 5. CSRF Protection (للـ mutating requests) 6. Auth Middleware (JWT أو API Key) 7. Multi-tenancy Scope (inject organization_id في كل query) تفاصيل الـ Multi-tenancy: - كل request يحتوي على organization_id من الـ JWT - يجب inject هذا الـ ID في كل database query تلقائياً - بعض الجداول معفاة (organizations, permissions, license_records) - Super Admin يستطيع تحديد X-Organization-ID header لتجاوز الـ scope تفاصيل الـ CSRF: - Token يُولَّد عند Login - يُخزن في HTTP-only cookie - يجب إرساله في X-CSRF-Token header مع كل mutating request - GET/HEAD/OPTIONS معفاة المطلوب: صمم هذه الـ middleware chain وأخبرني: 1. ما هو الترتيب الصحيح وسبب كل قرار؟ 2. كيف يعمل الـ Multi-tenancy scope تقنياً؟ 3. كيف أتعامل مع API Keys (بديل JWT للـ programmatic access)؟ 4. ما هي الـ endpoints المعفاة من الـ Auth؟

Security Hardening الكامل
CSRF، SSRF protection، Rate Limiting، Input Validation، SQL Injection prevention، Security Headers
أريد مراجعة أمنية شاملة لمشروع WhatsApp Business Platform قبل النشر. مجالات الأمان المطلوب التحقق منها: 1. Authentication Security: - هل الـ JWT signing key قوية كافياً؟ - هل الـ Refresh Token Rotation مُطبَّق بشكل صحيح؟ - هل يوجد حماية من Brute Force على Login؟ - هل الـ Cookies محمية بـ HttpOnly, Secure, SameSite؟ 2. CSRF Protection: - هل كل mutating requests محمية بـ CSRF token؟ - هل الـ WebSocket محمية؟ 3. SSRF Protection: - الـ Custom Actions و AI Contexts و Webhooks تستدعي URLs خارجية - هل يتم فحص الـ IPs قبل الاتصال؟ - ما هي الـ IP ranges المحظورة؟ 4. Input Validation: - هل كل المدخلات تُتحقق منها؟ - هل يوجد حماية من XSS في الرسائل؟ - هل حجم الـ requests محدود؟ 5. WhatsApp Webhook Security: - هل الـ HMAC-SHA256 signature يُتحقق منها دائماً؟ - هل هناك حماية من Replay Attacks؟ 6. Rate Limiting: - Login: max 5 attempts/IP/hour - Message sending: per user per minute - Webhook calls: per endpoint - API Keys: configurable limits 7. Data Security: - هل الحقول الحساسة مشفرة في قاعدة البيانات؟ - هل الـ Multi-tenancy isolation محكمة؟ - هل يوجد حماية من Cross-tenant data leaks؟ المطلوب: راجع كل نقطة وأخبرني: 1. ما الذي يحتاج تحسين في كل مجال؟ 2. ما هي الثغرات الشائعة في هذا النوع من المشاريع؟ 3. ما هي أهم الأولويات؟

Production Deployment + Monitoring
Docker production setup، Nginx config، Health checks، Logging، Metrics، Backup strategy
أريد نشر منصة WhatsApp Business على VPS في بيئة إنتاج آمنة وموثوقة. متطلبات الإنتاج: - Single VPS (البداية) - Multi-tenant: عدة منظمات على نفس الـ instance - أو Multi-instance: منظمة لكل sub-domain Stack الإنتاج: - Backend: binary app مع embedded frontend - PostgreSQL: قاعدة البيانات الرئيسية - Redis: Cache وQueue وPub/Sub - Nginx: Reverse Proxy وSSL termination - Certbot: SSL certificates التكوين المطلوب: 1. Docker Compose للإنتاج: - Services: app, postgres, redis, nginx - Volumes: postgres_data, redis_data, uploads - Networks: internal network بين الخدمات - Health checks لكل service - Restart policy: always 2. Nginx Configuration: - SSL/HTTPS مع Let's Encrypt - WebSocket proxy (upgrade headers) - Rate limiting - Gzip compression - Static file caching - Large file upload support 3. Monitoring: - /health endpoint للتحقق من حالة الخدمة - /ready endpoint للتحقق من جاهزية الخدمات - /metrics endpoint (Prometheus) - Log aggregation (structured JSON logs) 4. Backup Strategy: - PostgreSQL: daily automated backup - Uploads: sync to object storage - Redis: periodic RDB snapshots 5. Zero-Downtime Deployment: - Build new binary - Hot-reload أو graceful restart المطلوب: 1. كيف أعد بيئة إنتاج متكاملة؟ 2. كيف أتعامل مع WebSocket في Nginx؟ 3. كيف أطبق Zero-Downtime Deployments؟ 4. ما هي أفضل ممارسات الـ backup؟ 5. كيف أُفعّل HTTPS تلقائياً؟
