Why use ACP?

Persistent Memory

LLMs drop context between sessions or when token limits are reached. ACP creates a hard drive for the AI directly inside your repository, guaranteeing it never forgets decisions or progress.

Anti-Hallucination

By forcing the AI to read your structured `design/` and `patterns/` documents before writing code, it stops breaking things by making wild assumptions. It stays architecturally aligned.

Step-by-Step Focus

Stops the "let me code the whole feature in one giant blob" behavior. ACP breaks large goals into Milestones, and Milestones into single, achievable Tasks.

Self-Auditing

Documentation drift is a massive problem. Commands like @acp.sync allow the AI to read your codebase, find where the documentation is wrong, and auto-correct the docs.

Directory Structure

The ACP framework lives inside the agent/ folder at the root of your project. Here is how the AI expects your files to be organized:

your-project/
├── agent/
│   ├── commands/       # AI executable macros (e.g., acp.init.md)
│   ├── design/         # Architecture & Feature Specifications
│   ├── milestones/     # High-level tracking & Deliverables
│   ├── patterns/       # Reusable code/architecture patterns
│   ├── tasks/          # Actionable, uncompleted units of work
│   ├── reports/        # Generated status reports
│   └── progress.yaml   # The persistent Brain/State of the AI

The Development Workflow

How to correctly tell the AI to implement a robust, reliable feature.

Step 1

Define the Architecture (Design)

Before writing a single line of code, you force the AI to write a specification. This solves the "how" and constraints of the feature.

What you say to the AI:

"I want to build a [Feature Name]. Let's create a design document for it in agent/design/ using the design template. Take into account [Constraint X] and [Goal Y]."

agent/design/auth-design.md (What the AI generates) 
# Feature: Multi-tenant JWT Authentication

**Concept**: Isolate sessions securely using partitioned JWT signing.
**Status**: Proposal

## Problem Statement
Standard JWTs leak data globally if the private key falls.

## Solution
Generate dynamic namespace sub-keys wrapped inside the Redis layer...
...
## Trade-offs
- Slight latency penalty parsing namespace definitions on initial handshake.
Step 2

Break It Down (Milestones & Tasks)

Once the design is approved, you tell the AI to break the massive feature into quantifiable, trackable units of work. This sets up the actual project management files.

What you say to the AI:

"Please create a new Milestone document in agent/milestones/ for this feature. Then, generate the corresponding sequential Tasks in agent/tasks/. Finally, update agent/progress.yaml to register these as not_started."

agent/milestones/milestone-4-auth.md

  • Goal: Implemenet Multi-tenant JWT auth
  • [ ] Create security adapters
  • [ ] Tie hooks to fastglue router

agent/progress.yaml

tasks: milestone_4: - id: task-1 status: not_started

Step 3

Execute the Code Work

This is where the magic happens. You simply invoke the ACP action macro. The AI will look at progress.yaml, find the first uncompleted task, open it, and immediately start writing backend or frontend code to satisfy it.

@[agent/commands/acp.proceed.md]

The Implementation Command

AI Behavior Triggered:
  • Reads `progress.yaml` to find "task-1"
  • Reads `agent/tasks/task-1.md`
  • Systematically writes `.go` files or `.vue` files
  • Runs linters or builds to verify code

@[agent/commands/acp.update.md]

The Check-In Command

When I finish coding the task successfully, type this to tell me to mark it complete and calculate our new progress percentage.

Step 4

Housekeeping (Sync & Validating)

Sometimes during coding, we realize the original design was flawed so we pivoted in the code. ACP manages this "documentation drift" gracefully.

@[agent/commands/acp.sync.md]

Reads your actual codebase components and compares them to the design documents. If the code did something different, it automatically rewrites the documentation to match the real code.

@[agent/commands/acp.validate.md]

Scans the `agent/` folder looking for broken links, missing fields, corrupted YAML syntax, or files that didn't follow the proper ACP template restrictions.
