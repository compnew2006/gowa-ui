<div dir="rtl">الأمان</div>

يطبق Whatomate طبقات متعددة من الأمان لحماية البيانات أثناء النقل وفي حالة السكون وأثناء المعالجة.

## المصادقة

### مصادقة JWT

يستخدم Whatomate JWT (رموز الويب JSON) مع توقيع HS256 لمصادقة API.

**أنواع الرموز:**

| الرمز | العمر | الغرض |
|-------|-----|---------|
| رمز الوصول | 15 دقيقة | مصادقة طلبات API |
| رمز التحديث | 7 أيام | الحصول على رموز وصول جديدة |
| رمز WebSocket | 30 ثانية | مصادقة اتصال WebSocket |

**ادعاءات الرمز:**

```json
{
  "sub": "refresh",
  "user_id": 1,
  "org_id": 1,
  "role_id": 1,
  "permissions": ["contacts:read", "messages:write"],
  "jti": "unique-token-id",
  "exp": 1700000000,
  "iat": 1699999990
}
```

### تدوير رمز التحديث

تستخدم رموز التحديث نمط التدوير لمنع هجمات إعادة التشغيل:

1. عند تسجيل الدخول، يتم تخزين JTI (معرف رمز JWT) في Redis
2. عند التحديث، يتم التحقق من JTI و**حذفه** من Redis (استخدام واحد)
3. يتم إنشاء زوج رموز جديد مع JTI جديد
4. إذا تم تقديم JTI محذوف مرة أخرى، فهذا يشير إلى هجوم إعادة تشغيل ويتم رفضه

```
تسجيل الدخول → تخزين JTI-A في Redis
التحديث → التحقق من وجود JTI-A → حذف JTI-A → إنشاء JTI-B → تخزين JTI-B
إعادة التشغيل → التحقق من JTI-A → غير موجود → رفض (تم اكتشاف هجوم إعادة تشغيل)
```

### أمان ملفات تعريف الارتباط

يتم تخزين رموز المصادقة في ملفات تعريف ارتباط HTTP-only وSecure وSameSite=Strict:

| ملف تعريف الارتباط | الغرض | العلامات |
|--------|---------|-------|
| `whm_access` | رمز الوصول | HTTP-only, Secure, SameSite=Strict |
| `whm_refresh` | رمز التحديث | HTTP-only, Secure, SameSite=Strict |
| `whm_csrf` | رمز CSRF | HTTP-only, Secure, SameSite=Strict |

### مصادقة SSO

تستخدم مزودي SSO (Google، Azure AD، إلخ) OAuth2 مع حماية CSRF عبر رمز الحالة:

1. إنشاء رمز حالة (حماية CSRF)
2. إعادة التوجيه إلى عنوان URL الخاص بالمزود
3. تبادل رمز التفويض مع الرموز
4. جلب معلومات المستخدم وإنشاء/العثور على المستخدم المحلي
5. إنشاء زوج JWT وتعيين ملفات تعريف الارتباط

## حماية CSRF

يتم فرض الحماية من تزوير الطلبات عبر المواقع على جميع طلبات التعديل:

```
POST/PUT/DELETE/PATCH → استخراج رأس X-CSRF-Token
                       → مقارنته بملف whm_csrf
                       → تطابق → المتابعة
                       → عدم تطابق → 403 محظور

GET/HEAD/OPTIONS → تخطي فحص CSRF
```

## تشفير البيانات

### تشفير AES-256-GCM

يتم تشفير البيانات الحساسة في حالة السكون باستخدام AES-256-GCM:

```go
// التشفير
ciphertext := crypto.Encrypt(plaintext)  // يعيد "enc3:<base64>"

// فك التشفير
plaintext, err := crypto.Decrypt(ciphertext)
```

**الحقول المشفرة:**

| النموذج | الحقول |
|-------|--------|
| WhatsAppAccount | access_token, phone_number_id, business_account_id, webhook_verify_token |
| SSOProvider | client_secret |
| ChatbotSettings | ai_api_key |
| Webhook | secret |
| CustomAction | headers |

### إصدارات التشفير

| الإصدار | البادئة | الحالة |
|---------|--------|--------|
| enc1 | `enc:` | قديم — يجب ترحيله |
| enc2 | `enc2:` | قديم — يجب ترحيله |
| enc3 | `enc3:` | الحالي (AES-256-GCM) |

شغّل ترحيل التشفير لترقية البيانات القديمة:

```bash
whatomate crypto-migrate
```

## متصل SSRF الآمن

تستخدم طلبات HTTP الصادرة متصلاً آمناً يمنع الطلبات إلى نطاقات IP الداخلية:

**النطاقات المحظورة:**

| النطاق | النوع |
|-------|------|
| `127.0.0.0/8` | Loopback |
| `10.0.0.0/8` | خاص |
| `172.16.0.0/12` | خاص |
| `192.168.0.0/16` | خاص |
| `169.254.0.0/16` | رابط محلي |
| `::1` | IPv6 loopback |
| `fc00::/7` | IPv6 محلي فريد |
| `fe80::/10` | IPv6 رابط محلي |

## سياسات تقييد الإرسال

### إعدادات على مستوى المؤسسة

| الإعداد | الوصف |
|---------|-------------|
| `strict_sending_restrictions_enabled` | التبديل الرئيسي لوضع الإرسال الصارم |
| `outbound_mode` | "inbound_only" (رد فقط) أو "mixed" (صادر كامل) |
| `strict_sending_apply_to_system` | تطبيق القيود على رسائل chatbot/النظام |
| `campaign_draft_only` | تقييد الحملات بوضع المسودة فقط |
| `strict_rollout_mode` | "audit" (تسجيل الانتهاكات) أو "enforce" (حظر الرسائل) |
| `strict_rollout_enforce_at` | الطابع الزمني لبدء التنفيذ |

### إعدادات على مستوى المستخدم

| الإعداد | الوصف |
|---------|-------------|
| `enabled` | تبديل القيود لهذا المستخدم |
| `include_all_contacts` | السماح بجميع جهات الاتصال أو تقييد القائمة البيضاء |
| `authorized_numbers` | القائمة البيضاء لأرقام الهواتف المسموحة |
| `allowed_instance_id` | نسخة محددة يمكن للمستخدم الإرسال منها |
| `allowed_instance_ids` | نسخ متعددة يمكن للمستخدم الإرسال منها |
| `prefix_agent_name` | بادئة تلقائية للرسائل باسم الوكيل |
| `allow_unclaimed_chat_view` | السماح بعرض المحادثات غير المطالب بها |
| `allow_unclaimed_chat_send` | السماح بالإرسال إلى محادثات غير مطالب بها |

### أوضاع التنفيذ

**وضع التدقيق:** تسجيل الانتهاكات مع السماح للرسائل بالمرور.

**وضع التنفيذ:** حظر الرسائل التي تنتهك القيود مع `restrictedSendViolationError`.

## قيود رؤية محادثات الوكيل

يتمتع مستخدمو دور الوكيل برؤية مقيدة:

- يرون فقط المحادثات المعينة لهم
- يرون فقط المحادثات العامة (`is_public = true`)
- يرون فقط المحادثات التي هم متعاونون فيها

ينطبق هذا حتى لو كان لدى الوكيل إذن `contacts:read`.

## رؤوس الأمان

تتضمن جميع استجابات HTTP رؤوس أمان:

| الرأس | القيمة | الغرض |
|--------|-------|---------|
| `X-Content-Type-Options` | `nosniff` | منع استكشاف نوع MIME |
| `X-Frame-Options` | `DENY` | منع الاختراق بالنقر |
| `X-XSS-Protection` | `1; mode=block` | تمكين متصفح فلتر XSS |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | التحكم في معلومات المرجع |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=()` | تقييد ميزات المتصفح |

## تحديد المعدل

يتم فرض تحديد المعدل على مستويات متعددة:

| المستوى | المفتاح | الحد الافتراضي |
|-------|-----|---------------|
| لكل مستخدم | `user_id:org_id` | 1000 طلب/نافذة |
| لكل عنوان IP | عنوان IP | 100 طلب/نافذة |
| نقاط نهاية المصادقة | عنوان IP | حد أقل |
| الرسائل الصادرة | المستخدم | قابل للتكوين |
| Webhooks | نقطة النهاية | قابل للتكوين |

تستخدم حدود المعدل عدادات Redis مع نوافذ منزلقة. تجاوز الحدود يعيد HTTP 429.

## سياسة كلمة المرور

يجب أن تستوفي كلمات المرور هذه المتطلبات:

| القاعدة | المتطلب |
|------|-------------|
| الحد الأدنى للطول | 8 أحرف |
| أحرف كبيرة | حرف كبير واحد على الأقل |
| أحرف صغيرة | حرف صغير واحد على الأقل |
| رقم | رقم واحد على الأقل |
| حرف خاص | حرف خاص واحد على الأقل |
| كلمات مرور شائعة | ليست في قائمة كلمات المرور الشائعة |

يتم التحقق أثناء التسجيل وتغييرات كلمة المرور.

## قائمة التحقق الأمنية

- [ ] مفتاح تشفير قوي (32 بايت، فريد لكل بيئة)
- [ ] سر JWT قوي (32+ حرفاً)
- [ ] تدوير بيانات اعتماد قاعدة البيانات بانتظام
- [ ] تعيين كلمة مرور Redis (ليست فارغة)
- [ ] تقييد CORS `allowed_origins` لنطاقات معروفة
- [ ] `debug = false` في الإنتاج
- [ ] إنهاء SSL/TLS عند الوكيل العكسي
- [ ] تمكين تحديد المعدل
- [ ] تكوين قيود الإرسال للامتثال
- [ ] تمكين تسجيل النشاط لمسار التدقيق
- [ ] فحوصات مستشار الأمان المنتظمة (شغّل `get_advisors`)
