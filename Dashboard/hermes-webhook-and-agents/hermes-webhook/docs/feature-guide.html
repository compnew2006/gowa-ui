Hermes Webhook Feature Guide

This page documents the new Hermes webhook behavior: KB-constrained public replies, instant human-reply learning for unknown comments, and Facebook comment-to-Messenger private replies with predefined templates or mirrored learned human replies, plus Telegram teaching commands.

Overview

What the system does

  • Answers factual customer questions only from the markdown knowledge base.
  • Uses strict fallbacks when the answer is not in the KB.
  • Can learn safe human public replies instantly when a comment originally used the exact unknown fallback.
  • Can send a private Messenger reply after a valid public comment reply.
  • Pushes a Telegram alert when a new human reply is learned successfully.
  • Lets the owner teach, list, and remove learned replies directly from Telegram.

What it does not do

  • It does not write customer interactions into the authoritative KB.
  • It does not reuse learned replies when the KB already has an answer.
  • It does not learn suspicious, unsafe, or case-specific human replies.
  • It does not send private DMs for raw unknown fallbacks that have not been learned yet.
The safest model is: the KB always answers supported business questions first, and learned human replies are used only when the bot would otherwise send the exact unknown fallback.

Public Reply Flow

1. Customer comment arrives The webhook receives a Facebook Page feed comment event.
2. The responder classifies the message It checks the KB-backed categories first and falls back only when the message is not supported by the approved knowledge sections.
3. KB answer first If the answer exists in the approved KB sections, the reply is generated from that data only.
4. Exact fallback when unsupported If the answer is not in the KB, the public reply stays the fixed unknown-answer phrase.
Public replies remain plain text only. Internal analysis never appears to the customer.

Instant Human Learning

This is the part that fixes your VPS case. The learning is immediate and automatic. No user action, no restart, and no manual retraining step is needed.

How it works

1. The bot replies publicly If the comment is unsupported, it may reply with the exact unknown fallback.
2. A human agent replies publicly to the same comment The webhook receives the page’s own comment event with a parent_id pointing to the original customer comment.
3. The server links the human reply to the original customer text The original customer comment text is already stored in a separate comment context log.
4. The next exact-normalized unknown comment reuses the human reply If another customer writes the same unknown message after normalization, the learned human reply is applied instantly.
Example: a customer asks an unsupported question, the bot sends the exact unknown fallback, then a human replies publicly with the correct answer. The next customer who sends the same normalized unknown message can get that learned human reply automatically.
When a new learned reply is saved successfully, Hermes also pushes a Telegram notification to the configured page owner chat with the original customer comment, the learned reply text, and the parent comment reference.
Learning only activates when the original bot reply was the exact unknown fallback. The learned reply must also pass safety checks and expires after 90 days. KB answers always win.

Private Messenger Replies

The webhook can send a private Messenger reply after a successful public reply, but only for supported KB-grounded intents or safe learned human replies.

Rule Behavior
Scope Facebook Page post comments only
Allowed intents pricing, location, hours, services, contact, greeting
Message source KB-grounded intents use predefined templates. Learned human replies mirror the same public reply text in Messenger.
Template placeholders {customer_name} and {public_reply} only
Language Matches the detected comment language, with English fallback for the same intent
Duplicate protection One private DM per comment via a dedicated private-reply log
The DM feature should remain disabled until the live Meta app permissions and the current Graph API private-reply edge are confirmed in production.

Telegram Teaching

The page owner can teach Hermes directly from Telegram. Taught replies are saved to the same live learned-reply store and become active immediately for the next exact-normalized fallback match.

Command Behavior
/teach سلام عليكم => وعليكم السلام ورحمة الله وبركاته كيف اقدر اساعدك Teach a new reply instantly for the current page.
/teach
q: سلام عليكم
a: وعليكم السلام ورحمة الله وبركاته كيف اقدر اساعدك		 Multiline version of the same teach command.
/learned Show active taught replies for the page.
/remove سلام عليكم Deactivate the active taught reply for that normalized phrase immediately.
Telegram teaching is owner-chat-only, page-scoped, and still fallback-only. If the KB has an answer, the KB continues to win over Telegram-taught replies.

What to verify

  • GET /health returns healthy JSON.
  • POST /debug/reply-preview returns grounded KB replies.
  • An unknown comment uses the learned human reply only after a Page public reply is received for the original fallback thread.
  • Punctuation-only or Arabic-variant formatting changes still match, but reordered wording does not.

Troubleshooting

If the bot does not learn from the human reply

  • Check that the human reply actually appears as a Page feed comment webhook event.
  • Check that the page reply event contains a valid parent_id pointing to the original customer comment.
  • Check webhook_events.log for the page reply event.
  • Check that a new row appears in {page_id}_learned_replies.jsonl.
  • Check that the parent comment context recorded used_unknown_fallback: true.
  • Check that the human reply does not contain blocked content such as URLs, phone numbers, fraud warnings, or case-specific promises.
  • Check that the learned reply is not older than 90 days.

If private DMs do not send

  • Confirm messenger_private_replies_enabled is set to true.
  • Confirm the intent is one of the configured DM question types.
  • Confirm the public reply was successful first.
  • Confirm the page has the needed Meta messaging permissions in production.
