# <div dir="rtl">الحملات</div>

أنشئ وأدِر وراقب حملات مراسلة واتساب الجماعية. أرسل رسائل قالب إلى مجموعات كبيرة من جهات الاتصال مع تأخيرات قابلة للتخصيص وجدولة وإمكانيات إعادة محاولة.

## نظرة عامة على الحملة

ترسل الحملة رسائل قالب واتساب إلى قائمة مستلمين. تتابع كل حالة التسليم ومعدلات النجاح والإخفاقات في الوقت الفعلي.

### حالات الحملة

| الحالة | الوصف |
|-------|-------------|
| **مسودة** | تم إنشاء الحملة ولكن لم تبدأ بعد |
| **قيد التشغيل** | يتم إرسال الرسائل |
| **متوقفة مؤقتاً** | تم الإيقاف مؤقتاً |
| **مكتملة** | تمت معالجة جميع المستلمين |
| **ملغاة** | تم إيقاف الحملة قبل الاكتمال |

## إنشاء حملة

**نقطة النهاية:** `POST /api/campaigns`

```json
{
  "name": "عرض العطلة",
  "whatsapp_account_id": "account-uuid",
  "template_id": "template-uuid",
  "body_content": "مرحباً {{1}}، تحقق من عروض العطلات لدينا!",
  "header_media_id": "media-uuid",
  "min_delay_seconds": 20,
  "max_delay_seconds": 45,
  "scheduled_at": "2024-12-01T09:00:00Z"
}
```

**المتطلبات:**

- يجب أن يكون القالب موجوداً وبحالة **معتمد**
- يجب أن يكون حساب واتساب نشطاً
- يجب أن تكون إعدادات التأخير ضمن النطاق المقبول (الحد الأدنى 20 ثانية، الحد الأقصى 45 ثانية افتراضياً)
- يجب إضافة مستلم واحد على الأقل قبل البدء

## عرض الحملات

**نقطة النهاية:** `GET /api/campaigns`

قم بتصفية الحملات حسب:

| الفلتر | الوصف |
|--------|-------------|
| **الحالة** | تصفية حسب حالة الحملة |
| **الحساب** | تصفية حسب حساب واتساب |
| **البحث** | البحث باسم الحملة |
| **النطاق الزمني** | تصفية حسب تاريخ الإنشاء |

يتضمن كل إدخال حملة إحصائيات تقدم في الوقت الفعلي:

```json
{
  "id": "campaign-uuid",
  "name": "عرض العطلة",
  "status": "running",
  "total_recipients": 500,
  "sent_count": 234,
  "delivered_count": 210,
  "failed_count": 5,
  "progress_percent": 46.8,
  "template": { "name": "holiday_promo" },
  "account": { "name": "الحساب الرئيسي" }
}
```

## تحديث حملة

**نقطة النهاية:** `PUT /api/campaigns/{id}`

تحديث تفاصيل الحملة. **ملاحظة:** لا يمكن تعديل الحملات النشطة أو قيد التشغيل.

## حذف حملة

**نقطة النهاية:** `DELETE /api/campaigns/{id}`

إزالة حملة. **ملاحظة:** لا يمكن حذف الحملات النشطة أو قيد التشغيل.

## إدارة المستلمين

### استيراد المستلمين

**نقطة النهاية:** `POST /api/campaigns/{id}/recipients/import`

ارفع ملف CSV أو JSON يحتوي على بيانات المستلمين:

```csv
phone_number,name,param1,param2
+1234567890,Alice,order_123,10
+0987654321,Bob,order_456,20
```

**ما يحدث:**

1. يتم تحليل الملف والتحقق منه
2. يتم التحقق من أرقام الهواتف للتنسيق الصحيح
3. يتم إدراج المستلمين بشكل جماعي في الحملة
4. يتم تحديث عدد `total_recipients` للحملة

### عرض المستلمين

**نقطة النهاية:** `GET /api/campaigns/{id}/recipients`

عرض جميع المستلمين مع حالة التسليم الفردية لكل منهم:

| الحالة | الوصف |
|--------|-------------|
| **قيد الانتظار** | لم تتم معالجته بعد |
| **مُرسل** | تم إرسال الرسالة بنجاح |
| **مُسلَّم** | تم تسليم الرسالة للمستلم |
| **فشل** | فشل الإرسال (مع سبب الخطأ) |
| **ملغي** | تم التخطي بسبب إلغاء الحملة |

### إزالة مستلم

**نقطة النهاية:** `DELETE /api/campaigns/{id}/recipients/{recipientId}`

إزالة مستلم معين من الحملة.

## تشغيل حملة

### البدء

**نقطة النهاية:** `POST /api/campaigns/{id}/start`

قبل البدء، يتحقق النظام من:

1. الحملة لديها مستلم واحد على الأقل
2. القالب معتمد
3. حساب واتساب نشط
4. إعدادات التأخير صالحة

**ما يحدث:**

1. تتغير حالة الحملة إلى `running`
2. يتم نشر المستلمين في طابور معالجة Redis
3. يلتقط العمال الوظائف ويرسلون الرسائل بتأخير عشوائي
4. يتم بث التقدم عبر WebSocket في الوقت الفعلي

### إيقاف مؤقت

**نقطة النهاية:** `POST /api/campaigns/{id}/pause`

إيقاف الإرسال مؤقتاً. سيتخطى العمال المستلمين من الحملات المتوقفة. يمكن استئناف الحملة لاحقاً.

### إلغاء

**نقطة النهاية:** `POST /api/campaigns/{id}/cancel`

إيقاف الحملة بشكل دائم:

1. تتغير الحالة إلى `cancelled`
2. يتم وضع علامة ملغي على جميع المستلمين المعلقين
3. يتم تسجيل الطابع الزمني `completed_at`

### إعادة محاولة المستلمين الفاشلين

**نقطة النهاية:** `POST /api/campaigns/{id}/retry-failed`

إعادة محاولة الإرسال لجميع المستلمين الذين فشلوا سابقاً:

1. يتم إعادة تعيين المستلمين الفاشلين إلى حالة `pending`
2. يتم إعادة نشرهم في طابور المعالجة
3. يتم إعادة إرسال الرسائل بنفس القالب والتأخيرات

## وسائط الحملة

### رفع وسائط الحملة

**نقطة النهاية:** `POST /api/campaigns/{id}/media`

ارفع ملفات وسائط (صور، مستندات) لاستخدامها في رؤوس قالب الحملة.

### عرض وسائط الحملة

**نقطة النهاية:** `GET /api/campaigns/{id}/media`

استرجع ملفات وسائط الحملة المرفوعة.

## فرض سياسة الحملة

قبل إنشاء حملة أو تشغيلها، يتم التحقق من السياسات التالية:

| السياسة | التحقق |
|--------|-------|
| **موافقة القالب** | يجب أن يكون القالب بحالة APPROVED |
| **حالة الحساب** | يجب أن يكون حساب واتساب نشطاً |
| **التحقق من التأخير** | التأخير الأدنى/الأقصى ضمن النطاق المقبول |
| **التحقق من المستلمين** | مطلوب مستلم واحد على الأقل |
| **التحقق من الجدولة** | يجب أن يكون الوقت المجدول في المستقبل |
| **تحديد المعدل** | يتم فرض حدود معدل حملة المؤسسة |

إذا كانت مؤسستك لديها `campaign_draft_only` مفعّلاً في قيود الإرسال، يمكن فقط إنشاء الحملات في وضع المسودة ولا يمكن تشغيلها مباشرة.

## العناصر النائبة للقالب

تدعم رسائل الحملة عناصر نائبة ديناميكية يتم حلها لكل مستلم:

| العنصر النائب | يُحل من |
|-------------|---------------|
| `{{1}}`، `{{2}}`، إلخ. | معاملات خاصة بالمستلم من الاستيراد |
| `{{contact.name}}` | اسم جهة الاتصال |
| `{{contact.phone}}` | رقم هاتف جهة الاتصال |
| `{{user.name}}` | اسم الوكيل/المرسل |
| `{{organization.name}}` | اسم المؤسسة |

**مثال:** إذا كان نص قالبك هو `مرحباً {{1}}، طلبك {{2}} جاهز!`، والاستيراد يتضمن `param1=أحمد` و`param2=ORD-123`، تصبح الرسالة `مرحباً أحمد، طلبك ORD-123 جاهز!`.

## إعدادات التأخير

كل حملة لديها تأخير قابل للتكوين بين الرسائل لتجنب تحديد المعدل:

| الإعداد | الافتراضي | الوصف |
|---------|---------|-------------|
| **الحد الأدنى للتأخير** | 20 ثانية | أقل انتظار بين الرسائل |
| **الحد الأقصى للتأخير** | 45 ثانية | أقصى انتظار بين الرسائل |

يتم اختيار التأخير الفعلي لكل رسالة عشوائياً بين الحد الأدنى والأقصى لإنشاء أنماط إرسال طبيعية.

## المعالجة الخلفية

تتم معالجة رسائل الحملة بواسطة عمال الخلفية:

1. يلتقط العمال وظائف المستلمين من طابور Redis
2. يمنع القفل الموزع الإرسال المكرر لنفس المستلم
3. يتم تطبيق تأخير عشوائي قبل كل إرسال
4. يتم حل العناصر النائبة للقالب ببيانات المستلم
5. يتم إرسال الرسالة عبر مزود واتساب
6. يتم تحديث حالة المستلم وإحصائيات الحملة
7. يتم بث التقدم عبر WebSocket
