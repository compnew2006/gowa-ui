## خطة: استرجاع Catalog/Products backend + بناء الواجهة الأمامية

### السياق
الـ handlers اتسحت في الخطوة السابقة بس الـ models (`internal/models/catalog.go`) والـ WhatsApp client (`pkg/whatsapp/catalog.go`) والـ AutoMigrate موجودين. الـ upstream repo فيه الـ handlers الأصلية كاملة وجاهزة. التعديل مبني على نقل (restore) الـ backend + إضافة (add) الـ frontend.

---

### الجزء 1: Backend (restore) — 3 تعديلات

**1.1 — استرجاع ملف الـ handlers (نسخ من upstream)**
- نسخ `/tmp/whatomate_upstream/internal/handlers/catalog.go` → `internal/handlers/catalog.go` (17KB، 10 handlers + 2 helpers `catalogToResponse`/`productToResponse` + request/response structs).
- ✅ كل الـ dependencies اللي بيستخدمها موجودة عندنا: `getOrgID`, `parsePathUUID`, `findByIDAndOrg`, `resolveWhatsAppAccount`, `toWhatsAppAccount`, `decodeRequest`.
- ✅ مفيش تعارض أسماء (اتأكدنا إن الـ helpers `catalogToResponse`/`productToResponse` اتسحت مع الملف زمان).

**1.2 — إضافة الـ 10 routes في `cmd/whatomate/main.go`**
يُضاف بعد قسم Templates (حوالى السطر 798) في نفس المجموعة التي تم التحقق منها:
```go
// Catalogs & Products
g.GET("/api/catalogs", app.ListCatalogs)
g.POST("/api/catalogs", app.CreateCatalog)
```

**1.3 — اختبارات (Tests) (اختياري/مرغوب):** استرجاع `internal/handlers/catalog_test.go` من الـ upstream (37 اختبار). — يُفضل فعلها عشان الـ coverage.

**Backend verification:** `go build ./... && go vet ./... && go test ./internal/handlers/...`

### الجزء 2: Frontend — واجهة كاملة (pattern-matched)

مبنية على الأنماط اللي استكشفناها (TagsView/AccountsView للـ list, AccountDetailView للـ detail, CrudFormDialog للـ forms).

**2.1 — API service** (`frontend/src/services/api.ts`)
إضافة `catalogsService` + `productsService` بنفس نمط الـ services الموجودة:
```ts
export const catalogsService = {
  list: (params?) => api.get('/catalogs', { params }),
  get: (id) => api.get(`/catalogs/${id}`),
  create: (data) => api.post('/catalogs', data),
  delete: (id) => api.delete(`/catalogs/${id}`),
  sync: (data) => api.post('/catalogs/sync', data),
  products: (catalogId) => api.get(`/catalogs/${catalogId}/products`),
}
export const productsService = {
  get: (id) => api.get(`/products/${id}`),
  create: (catalogId, data) => api.post(`/catalogs/${catalogId}/products`, data),
  update: (id, data) => api.put(`/products/${id}`, data),
  delete: (id) => api.delete(`/products/${id}`),
}
```

**2.2 — طريقة العرض (Views) (ملفين جداد)**
- `frontend/src/views/settings/CatalogsView.vue` — قائمة (list) الكتالوجات بـ `PageHeader` + `DataTable` (عمود: name, account, product count, status, actions) + زر **Sync** (مهم — بيجيب الكتالوجات من Meta) + `CrudFormDialog` للإنشاء (create) (اسم + اختيار حساب WA).
- `frontend/src/views/settings/CatalogDetailView.vue` — تفاصيل (detail) الكتالوج بـ `DetailPageLayout`، وفيه قسم (sub-section) منتجات (Products) (`DataTable` + `CrudFormDialog` للإنشاء/التعديل للمنتج: name, price, currency, description, image_url, retailer_id).

**2.3 — الموجِّه (Router)** (`frontend/src/router/index.ts`)
إضافة مسارين (routes) + إدخال في `navigationOrder`:
```ts
{ path: 'settings/catalogs', name: 'catalogs', component: () => import('@/views/settings/CatalogsView.vue'), meta: { permission: 'catalogs' } },
{ path: 'settings/catalogs/:id', name: 'catalog-detail', component: () => import('@/views/settings/CatalogDetailView.vue'), meta: { permission: 'catalogs' } },
```

**2.4 — التنقل (Navigation)** (`frontend/src/components/layout/navigation.ts`)
إضافة `{ name: 'nav.catalogs', path: '/settings/catalogs', icon: ShoppingCart, permission: 'catalogs' }` كـ child للـ settings، + إضافة `'catalogs'` للـ `childPermissions` والـ `permissions`.

**2.5 — i18n** (`en.json` + `ar.json`)
إضافة: `nav.catalogs`/`nav.products`، `settings.catalogs`، ومساحة أسماء (namespace) `catalogs`/`products` كاملة (title, newCatalog, name, price, currency, sync, إلخ).

**Frontend verification:** `npm run typecheck` (في `frontend/`).
