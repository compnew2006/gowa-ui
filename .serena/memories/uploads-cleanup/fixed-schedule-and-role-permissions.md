Uploads cleanup is now separated from general settings behind a dedicated RBAC resource `settings.uploads_cleanup` (read/write/execute). Existing system admin roles needed an explicit DB backfill because permission seeding alone does not update already-seeded roles. The cleanup worker now runs on a fixed daily hour per organization timezone using `uploads_cleanup_schedule_hour` plus `uploads_cleanup_last_run_date`, with manual cleanup exposed through a dedicated HTTP handler. During implementation, E2E exposed a broader runtime issue: some handlers reused a stateful GORM request handle after prior queries, causing PostgreSQL `record not found` or wrong-column errors on later Create/Delete calls. For this feature, role and user write paths were stabilized by using clean write DB handles for create/update/delete operations.
