# نظرة عامة على المنصة

</div>

واتومات هو منصة شاملة لواجهة برمجة تطبيقات واتساب للأعمال تتيح للمؤسسات إدارة تواصل العملاء على نطاق واسع. يدعم بنيتين مزدوجتين للمزودين — واجهة Meta Cloud API وواتساب ويب المباشر (WhatsMeow) — مع ميزات قوية للمراسلة والحملات وأتمتة الدردشة والتعاون الجماعي.

## ما هو واتومات؟

واتومات هو منصة واتساب للأعمال متعددة المستأجرين وذاتية الاستضافة، مبنية بتقنية Go وReact. يوفر واجهة موحدة لإدارة محادثات واتساب بغض النظر عن مزود الواجهة الخلفية الذي تختاره.

## القدرات الرئيسية

| القدرة | الوصف |
|--------|-------|
| **المراسلة** | إرسال واستقبال الرسائل النصية والوسائط والقوالب والرسائل التفاعلية |
| **جهات الاتصال** | تنظيم والبحث وتصفية وتعيين جهات الاتصال لأعضاء الفريق |
| **الحملات** | المراسلة الجماعية مع الجدولة والتأخيرات وإعادة المحاولة والتحليلات الفورية |
| **الدردشة الآلية** | قواعد الكلمات المفتاحية والردود المدعومة بالذكاء الاصطناعي وسلاسل المحادثات ونقل العملاء للوكلاء |
| **الفرق** | التحكم في الوصول القائم على الأدوار وإدارة الفريق وميزات التعاون |
| **التحليلات** | مقاييس لوحة الأداء وأداء الوكيل وإحصائيات الدردشة الآلية والأدوات المخصصة |
| **التكاملات** | ربطات الويب الخارجية والإجراءات المخصصة ومصادقة SSO والوصول عبر API |
| **الأمان** | مصادقة JWT وحماية CSRF وتشفير AES-256-GCM وقيود الإرسال |

## بنية المزودين المزدوجة

يجرد واتومات اتصال واتساب من خلال واجهة `MessageProvider`، ويدعم واجهتين خلفيتين:

### واجهة Meta Cloud API

- واجهة واتساب للأعمال السحابية الرسمية من Meta
- تتطلب حساب Meta Business وموافقة التطبيق
- تدعم القوالب وسلاسل المحادثات والكتالوجات والمنتجات
- استقبال الرسائل عبر Webhook
- رسائل القوالب تتطلب موافقة Meta قبل الإرسال
- الأفضل للمؤسسات التي تحتاج التوافق مع الواجهة الرسمية

### WhatsMeow (واتساب ويب المباشر)

- يستخدم مكتبة `go.mau.fi/whatsmeow` لبروتوكول واتساب ويب المباشر
- المصادقة عبر رمز QR أو رمز الهاتف
- لا حاجة لموافقة القوالب — أرسل أي تنسيق رسالة
- طابور رسائل لكل مثيل مع تحديد المعدل
- اتصال WebSocket مباشر بخوادم واتساب
- الأفضل للفرق التي تريد المرونة بدون تأخيرات موافقة Meta

يتم اختيار المزود في `config.toml` تحت `whatsapp.provider`. الاختيار يحدد الميزات المتاحة — القوالب وسلاسل المحادثات والكتالوجات ميزات خاصة بـ Meta فقط.

## التصميم متعدد المستأجرين

يدعم واتومات مؤسسات متعددة على نشر واحد:

- **عزل المؤسسات**: كل مورد (جهات اتصال، حملات، دردشة آلية) مرتبط بمؤسسة
- **عضوية المستخدمين**: ينتمي المستخدمون للمؤسسات عبر سجلات `user_organizations`
- **تبديل المؤسسات**: يمكن للمستخدمين الذين لديهم وصول لمؤسسات متعددة تبديل السياق بسلاسة
- **إعدادات مستقلة**: كل مؤسسة لها إعدادات الدردشة الآلية والأدوار والفرق والإعدادات الخاصة بها
- **حذف متسلسل ناعم**: حذف المؤسسة يحذف ناعمًا جميع السجلات المرتبطة

## التحكم في الوصول القائم على الأدوار (RBAC)

يستخدم واتومات نظام أذونات دقيق:

| الدور | الأذونات الافتراضية |
|-------|---------------------|
| **المدير (Admin)** | وصول كامل لجميع الميزات والإعدادات |
| **المدير (Manager)** | إدارة الفريق والتحليلات ومعالجة التصعيدات |
| **الوكيل (Agent)** | معالجة الدردشات المعينة وإرسال الرسائل واستخدام الردود الجاهزة |
| **مخصص** | محدد من المؤسسة بأذونات resource:action محددة |

تُعرّف الأذونات كأزواج `resource:action` (مثل `contacts:read` و`messages:write` و`campaigns:delete`) وتُخزن مؤقتًا في Redis للأداء.

## بنية الوقت الفعلي

يوفر واتومات تحديثات فورية عبر قنوات متعددة:

- **WebSocket**: تواصل فوري موجه للعملاء للرسائل وتحديثات الحالة والإشعارات وتقدم الحملات
- **Redis Pub/Sub**: تواصل بين العمليات لإحصائيات الحملات والتنسيق بين المثيلات
- **طوابير Redis**: معالجة المهام الخلفية للحملات وتنزيل الوسائط

## نموذج الأمان

| الطبقة | الآلية |
|--------|--------|
| المصادقة | JWT (HS256) مع تبديل رموز الوصول والتحديث |
| الجلسة | ملفات تعريف ارتباط HTTP-only وSecure وSameSite=Strict |
| التفويض | RBAC مع فحوصات أذونات resource:action |
| تشفير البيانات | AES-256-GCM للحقول الحساسة (الرموز ومفاتيح API والأسرار) |
| حماية CSRF | نمط ملف تعريف الارتباط المزدوج |
| تحديد المعدل | حدود لكل مستخدم ولكل عنوان IP عبر Redis |
| منع SSRF | نطاقات IP محظورة لطلبات HTTP الصادرة |
| قيود الإرسال | سياسات إرسال الرسائل على مستوى المؤسسة والمستخدم |

## الجمهور المستهدف

صُمم واتومات لـ:

- **فرق دعم العملاء** التي تدير محادثات واتساب على نطاق واسع
- **فرق التسويق** التي تدير حملات مراسلة جماعية
- **المطورين** الذين يبنون تطبيقات متكاملة مع واتساب
- **الشركات** التي تحتاج دعم واتساب متعدد الوكلاء بدون SaaS خارجي

## متى تستخدم واتومات

| السيناريو | لماذا واتومات |
|-----------|---------------|
| دعم واتساب متعدد الوكلاء | تعاون الفريق والتعيين والدردشة الفورية |
| حملات المراسلة الجماعية | حملات مجدولة مع تأخيرات وتحليلات |
| خدمة العملاء الآلية | دردشة آلية مع كلمات مفتاحية وذكاء اصطناعي وسلاسل محادثات |
| واجهة واتساب API ذاتية الاستضافة | تحكم كامل في البيانات والبنية التحتية |
| إدارة المؤسسات المتعددة | نشر واحد يخدم فرقًا/علامات تجارية متعددة |

## متى لا تستخدم واتومات

- تحتاج أداة أتمتة واتساب شخصية بسيطة (استخدم حلًا أخف)
- تتطلب ميزات شريك Meta BSP الرسمية غير المدعومة بعد
- تحتاج SMS أو قنوات مراسلة أخرى (واتساب مخصص لواتساب فقط)
