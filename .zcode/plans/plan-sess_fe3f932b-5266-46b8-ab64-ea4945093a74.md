# Plan: Pending / Me Tabs with Takeover & Release

## Requirement (Arabic → English)
At the top of the side conversation list, add two tabs — **"pending"** and **"me"**. All conversations start in **pending**. A conversation moves to **me** when an agent takes it over via a button that replaces the conversation content (hiding messages). On takeover: (1) log to `/settings/audit-logs` that "user X took over the conversation", (2) insert a **system message** in the chat between messages. When done, a **"Leave conversation"** button returns it to **pending** and inserts a system message that it was released. Include **i18n** (AR/EN).

## Key Finding: ~80% already exists
Cross-validated by three explorations: the claim/collaborate/close lifecycle, system-message rendering (`metadata.is_system_message`), WS broadcasts, and the claim-screen overlay that hides messages are **all already built**. The genuinely new work is:
1. **Pending/Me tabs UI** (does not exist)
2. **Audit logging on takeover** — `ClaimChat` currently writes a system message + WS but **never calls `logAudit`**, so it never appears in `/settings/audit-logs`
3. **Release-to-pending path** — existing `LeaveChat` last-participant path goes to `closed`, not `pending`. Need a new `/release` endpoint
4. **System-message i18n** — currently hardcoded English strings baked into DB

## Stack (locked from markers)
- Backend: Go 1.25, fastglue, GORM, PostgreSQL, AutoMigrate (no SQL files)
- Frontend: Vue 3 `<script setup>` + TS + Pinia + vue-i18n (en.json is schema source; ar.json must mirror)
- Build: `go build ./...` / `cd frontend && npm run build` (Builder confirms exact commands)

## Decisions applied (recommended defaults — flag if you disagree)
- **D1 — Leave behavior:** Release **back to Pending** (matches "تعود مرة أخري في pending"). New `PUT /contacts/{id}/release` endpoint. Existing Close/Collab flows untouched.
- **D2 — Tab contents:** Pending = unassigned only (`chat_status==='pending' && !assigned_user_id`); Me = assigned-to-me (`assigned_user_id === me`). Closed & assigned-to-other hidden (handled via existing screens).
- **D3 — i18n scope:** **Full i18n** for all system messages by `system_type`, with `{agent}` interpolation.
- **D4 — Filtering:** **Client-side first** (filter loaded list in store). No backend list change; server-side can come later if pagination breaks.

## Tasks

### Backend (Go)

**T1. New `ReleaseChat` handler** — `internal/handlers/chat_lifecycle.go`
- `PUT /api/contacts/{id}/release`. Permission `chat.assign:write` (same as claim).
- Resets: `AssignedUserID = nil`, `SetStatus(ChatStatusPending)`, `ClearCollaborators()`, persist.
- System message: `createSystemMessage(..., "🔔 {name} released this conversation", JSONB{"system_type":"chat_released", "agent_id":...})`.
- Audit log: `a.logAudit(orgID, userID, "contact", contact.ID, AuditActionUpdated, &oldContact, &contact)` — **with `extraChanges` so the diff is non-empty** (the status lives in JSONB metadata; if ComputeChanges skips it, pass an explicit change via `extraChanges` to guarantee the entry isn't dropped — `audit.LogAudit` no-ops on empty `updated` diffs).
- WS broadcast: reuse `TypeChatClosed` payload shape but with `chat_status:"pending"`. Add new constant `TypeChatReleased = "chat_released"` in `internal/websocket`.

**T2. Add audit logging to `ClaimChat`** — same file, after the existing system message + WS block. Snapshot `oldContact := *contact` before the mutation. Same `extraChanges` safeguard as T1.

**T3. Register route** — `cmd/whatomate/main.go` near line 755: `g.PUT("/api/contacts/{id}/release", app.ReleaseChat)`.

**T4. (Optional) `contact` resource type in audit UI filters** — only if you want `/settings/audit-logs` filter dropdown to include contacts. The entries will still appear in the table + detail view regardless; only the dropdown filter is hardcoded. Small additions to `AuditLogsView.vue` (line ~165) and `resourceRouteMap` in `AuditLogDetailView.vue`. Include for completeness.

### Frontend (Vue/TS)

**T6. Store computeds + release action** — `frontend/src/stores/contacts.ts`
- `pendingContacts` computed: `sortedContacts` filtered to `c.chat_status === 'pending' && !c.assigned_user_id`.
- `myContacts` computed: `sortedContacts` filtered to `c.assigned_user_id === authStore.user?.id`.
- `activeListTab` ref + `displayedContacts` computed that switches between them (keeps group/newsletter filters applied).
- `releaseChat(contactId)`: `api.put('/contacts/${id}/release')`; locally set `assigned_user_id=null, assigned_user_name='', chat_status='pending'`; re-fetch messages.

**T7. Release button in chat header** — `ChatView.vue` around line 2169 (next to existing Leave button). Show only when `isAssignedToMe` (or admin/manager). Icon `LogOut`, label `$t('chat.leaveConversation')`. `handleRelease()` → `contactsStore.releaseChat`.

**T8. System-message i18n** — `ChatView.vue:2453-2462` + `getMessageContent` (1603).
- In the system-message block, switch from `getMessageContent(message)` to a new `getSystemMessageText(message)` that:
  - Reads `message.metadata.system_type`.
  - If present: `$t('chat.system.' + system_type, { agent: extractAgentFromContent(message) })`.
  - Else fallback to `getMessageContent(message)` (backward compat for old rows).
- Agent name: store it in `message.metadata.agent_name` (set on creation in T1/T2) so we don't parse the emoji-laden DB string. Old rows: extract from content via a regex on `"🔔 (.+?) claimed|released|closed..."` as a graceful fallback.

**T9. i18n keys** — both `frontend/src/i18n/locales/en.json` and `ar.json` (en is schema source, must match exactly):
- `chat.tabPending`, `chat.tabMe`, `chat.leaveConversation` (exists), `chat.releasedConversation`
- `chat.system.claimed` = `"{agent} claimed this conversation"` / `"{agent} استلم هذه المحادثة"`
- `chat.system.released` = `"{agent} released this conversation"` / `"{agent} أغلق المحادثة وأعادها للمعلّقة"`
- `chat.system.closed`, `chat.system.reopened`, `chat.system.joined`, `chat.system.left`, `chat.system.added`, `chat.system.ownership_transferred` — full parity for all existing `system_type` values so the i18n switch is complete.
