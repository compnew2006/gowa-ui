# Fix: Contacts not showing for connected GOWA devices

## Root cause (confirmed)
Connecting a GOWA device never imports contacts. There is no contact-sync anywhere in the codebase — contacts are only created lazily when a message arrives through a verified webhook (`contactutil.GetOrCreateContact`). So "devices connected but `/settings/contacts` is empty" is the expected state until messages flow.

The GOWA server **does** expose the data we need: `GET /chats` (confirmed in `docs/GOWA openapi.yaml:2420`) returns each conversation `{jid, name, last_message_time}`. We just never call it.

## Fix: add a "Sync Contacts" action per device
Pulls a connected device's chat list from GOWA and creates contact rows (idempotently), so the Contacts page populates immediately. Mirrors the existing `SyncGowaInstanceDevice` (`/sync`) handler and per-device button pattern exactly.

## Changes

### 1. Backend — GOWA client method (`pkg/gowa/chats.go`, NEW)
Add `ListChats(ctx, deviceID, opts) ([]Chat, total, error)`:
- Calls `GET /chats` with `X-Device-Id` header + query params (`limit` max 100, `offset`, `search`).
- Types: `Chat{JID, Name, LastMessageTime, ...}` and the `{code, message, results:{data, pagination:{total}}}` envelope (same shape as `ListDevices` in `devices.go:45`).
- Uses existing `doRaw` transport core. Loop pages internally (offset += limit until `total` reached) with a hard safety cap of 1000 chats to avoid runaway.

### 2. Backend — handler (`internal/handlers/gowa_instances.go`)
Add `SyncGowaInstanceDeviceContacts`:
- `POST /api/gowa/servers/{id}/devices/{deviceId}/sync-contacts`
- Permission: `devices:write` (matches sibling device actions).
- `resolveGowaInstance` + `parseDeviceID` (existing helpers).
- Resolve the `WhatsAppAccount` by `gowa_device_id` (reuse `getGowaAccountByDeviceID`); if missing → `409` with message "Run device sync first" (the existing `/sync` provisions the account row). This avoids side-effecting webhook setup during a contacts import.
- Call `client.ListChats(...)`, then for each chat:
  - 1:1 chat → `phone = PhoneFromJID(jid)`, `profileName = chat.Name`.
  - Group/newsletter (`@g.us`/`@newsletter`) → `phone = jid` (full JID, per webhook convention), `profileName = chat.Name`, set `metadata.is_group_chat = true`.
  - Reuse `contactutil.GetOrCreateContact(db, orgID, phone, name)` (idempotent, normalizes, restores soft-deletes).
  - Stamp `contact.WhatsAppAccount = account.Name` if empty (improves data quality; the normal webhook path doesn't set this, but manual/IVR creation does).
  - Skip empty/invalid JIDs.
- Return `{synced, created, total, device_id}` (synced = touched rows, created = new). Audit log entry.

### 3. Backend — route (`cmd/whatomate/main.go:715`, after the existing `/sync` line)
Register `g.POST("/api/gowa/servers/{id}/devices/{deviceId}/sync-contacts", app.SyncGowaInstanceDeviceContacts)`.

### 4. Frontend — API service (`frontend/src/services/api.ts`, `gowaServersService` ~line 985)
Add `deviceSyncContacts: (serverId, deviceId) => api.post(\`/gowa/servers/${serverId}/devices/${encodeURIComponent(deviceId)}/sync-contacts\`)`.

### 5. Frontend — UI (`frontend/src/views/settings/GowaServerDetailView.vue`)
Add a **"Sync Contacts"** button per device card in the existing `flex flex-wrap gap-1.5` button row (lines 503-559), following the exact `<Button size="sm" variant="ghost" @click="...">` + lucide icon pattern (use `UserPlus` or `RefreshCw`-style icon, e.g. `Users`/`Download`). Visible when `canWriteDevices && d.is_connected`. Handler:
- Calls `gowaServersService.deviceSyncContacts(serverId, d.id)`.
- On success: toast `"Synced {synced} contacts ({created} new)"`.
- On 409 ("sync first"): toast with guidance to click the existing **Sync** button first.
- Loading state on the clicked button; error toast on failure.
- Add i18n keys to `frontend/src/i18n/locales/en.json` + `ar.json` (e.g. `gowaServers.syncContacts`, `gowaServers.syncContactsSuccess`, `gowaServers.syncContactsNeedSync`).

## What this does NOT do
- Does **not** backfill message history (only contact rows). Messages flow via webhooks going forward — keeping the import cheap and avoiding huge history pulls. (Can be a follow-up if wanted.)
- Does **not** change the contacts list query — once rows exist, they show up immediately (the list has no device filter; confirmed).
- Does **not** touch webhook config — uses the existing `/sync` for account provisioning.
